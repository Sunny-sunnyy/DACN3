# CH-20261029-03 — Một chỗ lỗi không làm hỏng cả lượt tìm

29/10/2026 · Claude Code (Opus) · nhánh `toi-uu-search-key` · commit `c2f1b69`

## Giải thích ngắn
Trước đây một nguồn lỗi, một mô hình lỗi, hay gửi tin lỗi đều có thể làm mất cả lượt tìm; Amazon bị chặn lại hiện thành
"0 sản phẩm"; giao diện có thể treo "Processing..." mãi. Giờ mỗi nguồn báo trạng thái riêng, mô hình hỏng thì bị bỏ và chia
lại trọng số, deal hỏng thì bỏ deal, và chỉ gửi thông báo cho link BestBuy / Amazon.

## A. Trước
- `search_and_scrape`: `future.result()` ném lỗi của một nguồn lên trên.
- `EnsembleAgent.price`: một mô hình ném lỗi ⇒ cả deal lỗi; Frontier / Llama trả 0 khi không đọc được số ⇒ 0 đi thẳng vào
  trung bình (Frontier 0 kéo ước lượng xuống ~20 %).
- `search_key.py` worker không bắt lỗi ⇒ vòng lặp chờ kết quả mãi.
- `messaging_agent.push` bỏ qua mã HTTP.

## B. Sau
- `multi_source_planning_agent.py` `_run_source`: trạng thái `ok (n) / empty / blocked / error`; `amazon_deals.py` ném
  `AmazonBlockedError` khi WAF / CAPTCHA sau lần thử lại.
- `ensemble_agent.py` `combine`: chỉ lấy mô hình trả giá > 0, chia lại trọng số 0.8 / 0.1 / 0.1; không mô hình nào hợp lệ ⇒ lỗi.
  Kiểm offline 4 trường hợp (đủ, thiếu Llama, Frontier 0, tất cả hỏng) đúng công thức.
- `is_store_url`: chỉ gửi Pushover cho bestbuy.com / amazon.com (kiểm offline: chặn `amazon.com.evil.io`, `evilamazon.com`,
  `javascript:`). Nút gửi tay cũng kiểm.
- Push: `timeout=15`, HTTP ≠ 200 ⇒ báo lỗi; lỗi gửi không làm mất bảng kết quả.
- Gradio: lỗi pipeline hiện ở ô Status; Status kèm trạng thái từng nguồn.
- Kiểm hồi quy `air fryer`: 3 deal, BestBuy ok (5) + Amazon ok (6), luồng tự gửi tin chạy đúng (Pushover chặn khi đo).

## C. Còn tồn tại
- Trang 200 rỗng của Amazon vẫn báo `empty` (không phải `blocked`) vì chưa nhận dạng được trang đó.

## D. Kiểm độc lập
Agent con đọc diff: **major** — lỗi mới (push HTTP ≠ 200, ensemble không mô hình hợp lệ) có thể làm `price_is_right`
(`PlanningAgent`) treo ⇒ đã sửa ở CH-20261029-06.
