5. Kiến thức liên quan & Mở rộng
A. Inference Time vs. Training Time
Trong các tuần trước (1-5), bạn đã làm việc ở Inference Time (Thời gian suy luận):
•	Mô hình đã được huấn luyện xong ("đóng băng" trọng số).
•	Bạn dùng Prompt Engineering, In-context Learning (Few-shot), RAG để hướng dẫn mô hình đưa ra kết quả tốt hơn.
Từ tuần này, bạn chuyển sang Training Time (Thời gian huấn luyện):
•	Bạn can thiệp vào chính bộ não của mô hình.
•	Bạn thay đổi các tham số (weights) để mô hình học kiến thức mới hoặc hành vi mới vĩnh viễn (đối với phiên bản đó).
B. Generalization, Overfitting và Underfitting
Để hiểu sâu hơn về "Generalization" mà giảng viên nhấn mạnh:
•	Generalization (Tốt): Mô hình học được quy luật chung, đoán đúng cả trên dữ liệu mới.
•	Underfitting (Chưa học được): Mô hình quá đơn giản, không học được quy luật của dữ liệu (ví dụ: đoán giá sản phẩm nào cũng bằng nhau).
•	Overfitting (Học vẹt): Mô hình học quá kỹ các chi tiết nhiễu của dữ liệu huấn luyện. Nó đoán cực đúng trên tập Train nhưng đoán sai bét trên tập Test (dữ liệu mới).

6. Kiến thức liên quan & Mở rộng
Pre-training vs. Fine-tuning
•	Pre-training (Đào tạo trước): Là giai đoạn mô hình học kiến thức tổng quát từ lượng dữ liệu khổng lồ (Wikipedia, sách, internet...). Giai đoạn này tốn kém nhất và tạo ra "Base Model".
•	Fine-tuning (Tinh chỉnh): Là giai đoạn bạn lấy Base Model và dạy nó một kỹ năng cụ thể (ví dụ: đoán giá, viết code, y tế) bằng một lượng dữ liệu nhỏ hơn nhiều. Đây là trọng tâm công việc của một LLM Engineer.
LLM cho bài toán Regression (Hồi quy)
Thông thường LLM được biết đến với bài toán Generation (tạo văn bản - dự đoán token tiếp theo). Tuy nhiên, trong bài này, chúng ta ép LLM làm bài toán Regression (dự đoán một giá trị số).
•	Cách làm thường thấy: Yêu cầu LLM chỉ xuất ra con số (text) và ta parse con số đó.
•	Cách nâng cao (có thể học sau): Thay đổi lớp cuối cùng (output layer) của mạng nơ-ron để xuất ra một giá trị scalar thay vì xác suất của các token trong từ điển.

C. Chỉ số đánh giá (Evaluation Metrics)
Giảng viên phân biệt hai loại chỉ số:
•	Model-centric metrics (Kỹ thuật): Ví dụ như Cross-entropy loss. Tốt cho việc tối ưu mô hình nhưng khó hiểu với người làm kinh doanh.
•	Business-centric metrics (Kinh doanh): Ví dụ như doanh thu, sự hài lòng.
•	Lựa chọn cho dự án này: Absolute Price Difference (Sai số tuyệt đối về giá).
o	Lý do: Nó hữu hình và dễ hiểu (ví dụ: "Mô hình đoán sai 100 đô la").
o	So sánh: Trực quan hơn MSE (Mean Squared Error) - chỉ số thường dùng trong ML truyền thống nhưng con số (ví dụ: 10,000) khó hình dung ý nghĩa thực tế.
D. Chiến lược chia dữ liệu (Data Splitting Strategy)
Quy trình chuẩn để chia dữ liệu huấn luyện:
1.	Training Data (Tập huấn luyện): Chiếm phần lớn, dùng để cài đặt tham số cho mô hình.
2.	Validation Data (Tập xác thực - Held out): Dùng để đánh giá liên tục trong quá trình train, giúp quyết định khi nào dừng train hoặc chọn phiên bản mô hình nào tốt nhất.
3.	Test Data (Tập kiểm tra - Held out): Giữ kín đến tận cùng. Chỉ dùng 1 lần duy nhất sau khi đã chốt mô hình để đánh giá khả năng Generalization (khái quát hóa) khách quan nhất.

4. Phân tích Code (Mô phỏng)
Do bạn chưa cung cấp file code cụ thể, dưới đây là logic code Python (sử dụng thư viện datasets và pandas) mà bài học này thực hiện dựa trên mô tả của giảng viên:
1.	Load Data: Tải dataset McAuley-Lab/Amazon-Reviews-2023 từ Hugging Face.
2.	Filter/Clean: Loại bỏ các dòng thiếu giá (price) hoặc mô tả (description).

5. Kiến thức liên quan & Mở rộng
1. Tại sao chọn Absolute Error (MAE) thay vì Squared Error (MSE)?
•	MSE (Mean Squared Error): Bình phương sai số. Nó trừng phạt rất nặng các sai số lớn (outliers). Trong toán học, nó dễ đạo hàm (tính gradient) hơn.
•	MAE (Mean Absolute Error): Trị tuyệt đối. Trong bài toán dự đoán giá cả cho người dùng cuối (như dự án này), MAE phản ánh đúng tâm lý người mua ("Cái này đắt hơn giá trị thực bao nhiêu tiền?").
2. Data Leakage (Rò rỉ dữ liệu)
Khi chia dữ liệu (Train/Val/Test), một lỗi nghiêm trọng là để thông tin từ tập Test lọt vào tập Train. Ví dụ:
•	Dữ liệu trùng lặp: Cùng một sản phẩm xuất hiện ở cả Train và Test.
•	Kết quả: Mô hình học vẹt (Overfitting), điểm test rất cao nhưng ra thực tế dự đoán sai bét.
•	Lưu ý: Khi curate dataset Amazon, cần đảm bảo không có sản phẩm trùng lặp giữa các tập.

A. File parser.py - Bộ lọc và làm sạch dữ liệu
File này chứa logic "biến dữ liệu thô thành dữ liệu tinh".
Python
from pricer.items import Item
import json
import re

# --- CẤU HÌNH CÁC NGƯỠNG LỌC ---
MIN_CHARS = 600       # Chỉ lấy mô tả dài hơn 600 ký tự (để đảm bảo đủ thông tin huấn luyện)
MIN_PRICE = 0.5       # Loại bỏ rác hoặc phụ kiện quá rẻ
MAX_PRICE = 999.49    # Loại bỏ hàng xa xỉ/công nghiệp để tránh làm nhiễu mô hình
MAX_TEXT_EACH = 3000  # Giới hạn độ dài từng phần (mô tả, tính năng)
MAX_TEXT_TOTAL = 4000 # Giới hạn tổng độ dài văn bản đầu vào

# Các trường thông tin nhiễu cần loại bỏ
REMOVALS = [
    "Part Number",
    "Best Sellers Rank",
    "Batteries Included?",
    "Batteries Required?",
    "Item model number",
]

def simplify(text_list) -> str:
    """
    Hàm làm sạch chuỗi: xóa xuống dòng, tab, khoảng trắng thừa.
    """
    return (
        str(text_list)
        .replace("\n", " ")
        .replace("\r", "")
        .replace("\t", "")
        .replace("  ", " ") # Xóa khoảng trắng kép
        .strip()[:MAX_TEXT_EACH] # Cắt bớt nếu quá dài
    )

def scrub(title, description, features, details) -> bool:
    """
    Hàm kết hợp và làm sạch toàn bộ thông tin sản phẩm.
    """
    # 1. Loại bỏ các thông tin không quan trọng trong details
    for remove in REMOVALS:
        details.pop(remove, None)
    
    # 2. Ghép tiêu đề, mô tả, tính năng và chi tiết thành 1 chuỗi lớn
    result = title + "\n"
    if description:
        result += simplify(description) + "\n"
    if features:
        result += simplify(features) + "\n"
    if details:
        result += json.dumps(details) + "\n"
    
    # 3. Sử dụng Regex để xóa các mã sản phẩm (Product ID) vô nghĩa
    # Pattern tìm các chuỗi gồm chữ in hoa và số xen kẽ dài hơn 7 ký tự
    pattern = r"\b(?=[A-Z0-9]{7,}\b)(?=.*\d)[A-Z0-9]+\b"
    return re.sub(pattern, "", result).strip()[:MAX_TEXT_TOTAL]

def get_weight(details):
    """
    Hàm chuẩn hóa trọng lượng về đơn vị Pounds (lbs).
    Xử lý nhiều đơn vị khác nhau: ounces, grams, kg...
    """
    weight_str = details.get("Item Weight")
    if weight_str:
        parts = weight_str.split(" ")
        amount = float(parts[0])
        unit = parts[1].lower()
        # Chuyển đổi tất cả về pounds
        if unit == "pounds": return amount
        elif unit == "ounces": return amount / 16
        elif unit == "grams": return amount / 453.592
        # ... (các đơn vị khác)
    return 0

def parse(datapoint, category):
    """
    Hàm chính: Quyết định xem một sản phẩm có được đưa vào tập dữ liệu hay không.
    """
    try:
        price = float(datapoint["price"])
    except ValueError:
        return None # Bỏ qua nếu không có giá hợp lệ

    # Chỉ lấy sản phẩm trong khung giá quy định
    if MIN_PRICE <= price <= MAX_PRICE:
        title = datapoint["title"]
        description = datapoint["description"]
        features = datapoint["features"]
        details = json.loads(datapoint["details"])
        
        weight = get_weight(details)
        full = scrub(title, description, features, details) # Làm sạch văn bản
        
        # Chỉ lấy nếu văn bản sau khi làm sạch đủ dài (đủ dữ liệu để học)
        if len(full) >= MIN_CHARS:
            return Item(
                title=title,
                category=category,
                price=price,
                full=full,
                weight=weight,
            )

from pydantic import BaseModel
from datasets import Dataset, DatasetDict, load_dataset
from typing import Optional, Self

PREFIX = "Price is $"
QUESTION = "What does this cost to the nearest dollar?"

class Item(BaseModel):
    """
    Định nghĩa cấu trúc một điểm dữ liệu (Data Point)
    """
    title: str
    category: str
    price: float
    full: Optional[str] = None # Chuỗi văn bản đầy đủ đã làm sạch
    weight: Optional[float] = None
    # ... các trường khác

    def make_prompt(self, text: str):
        """Tạo prompt cho LLM: Câu hỏi + Nội dung + Giá (để training)"""
        self.prompt = f"{QUESTION}\n\n{text}\n\n{PREFIX}{round(self.price)}.00"

    @staticmethod
    def push_to_hub(dataset_name: str, train: list[Self], val: list[Self], test: list[Self]):
        """
        Đẩy dữ liệu lên Hugging Face Hub.
        Chuyển đổi list các object Item thành DatasetDict của Hugging Face.
        """
        DatasetDict(
            {
                "train": Dataset.from_list([item.model_dump() for item in train]),
                "validation": Dataset.from_list([item.model_dump() for item in val]),
                "test": Dataset.from_list([item.model_dump() for item in test]),
            }
        ).push_to_hub(dataset_name)

4. Phân tích Code: loaders.py
File này chứa công cụ để tải và xử lý dữ liệu quy mô lớn một cách hiệu quả (Parallel Processing).
Python
from datetime import datetime
from tqdm import tqdm
from datasets import load_dataset
from concurrent.futures import ProcessPoolExecutor
from pricer.parser import parse
import os

CHUNK_SIZE = 1000
# Tự động xác định số lượng CPU core để chạy song song
cpu_count = os.cpu_count()
WORKERS = max(cpu_count - 1, 1)

class ItemLoader:
    def __init__(self, category):
        self.category = category
        self.dataset = None

    def from_datapoint(self, datapoint):
        """
        Chuyển đổi một dòng dữ liệu thô thành object Item.
        Sử dụng hàm 'parse' (từ file parser.py đã học trước đó).
        """
        return parse(datapoint, self.category)

    def chunk_generator(self):
        """
        Kỹ thuật Generator: Thay vì load hết vào RAM, hàm này 'nhả' ra từng cục (chunk)
        dữ liệu (1000 dòng/lần) để xử lý dần.
        """
        size = len(self.dataset)
        for i in range(0, size, CHUNK_SIZE):
            yield self.dataset.select(range(i, min(i + CHUNK_SIZE, size)))

    def load_in_parallel(self, workers):
        """
        Xử lý song song (Parallel Processing):
        Đây là phần quan trọng nhất để xử lý 3 triệu dòng dữ liệu.
        Sử dụng ProcessPoolExecutor để chia việc cho các nhân CPU.
        """
        results = []
        chunk_count = (len(self.dataset) // CHUNK_SIZE) + 1
        # Tạo một hồ bơi các tiến trình (pool of workers)
        with ProcessPoolExecutor(max_workers=workers) as pool:
            # Map công việc xử lý chunk cho các workers
            for batch in tqdm(pool.map(self.from_chunk, self.chunk_generator()), total=chunk_count):
                results.extend(batch)
        return results

    def load(self, workers=WORKERS):
        """
        Hàm chính để gọi từ bên ngoài.
        1. Tải dataset thô từ Hugging Face.
        2. Gọi hàm xử lý song song để làm sạch và parse dữ liệu.
        """
        # ... (code loading dataset)
        results = self.load_in_parallel(workers)
        # ...
        return results
Tại sao cần load_in_parallel?
Vì việc xử lý chuỗi (string manipulation) trong Python tốn nhiều CPU. Với 3 triệu sản phẩm, nếu chạy tuần tự (vòng lặp for đơn thuần), bạn có thể mất hàng giờ. Kỹ thuật này tận dụng đa nhân CPU để giảm thời gian xuống còn vài phút.

•	Về loại: Quá nhiều đồ ô tô.
Hậu quả là mô hình sẽ có xu hướng đoán giá thấp cho mọi thứ (bias) vì làm vậy an toàn hơn. Để khắc phục, chúng ta cần kỹ thuật Sampling (lấy mẫu lại) - sẽ được đề cập trong phần tiếp theo của bài học (chọn lọc tập con dữ liệu để cân bằng lại phân phối).
C. Python Generators & Multiprocessing
•	Generators (yield): Giúp tiết kiệm RAM khi xử lý Big Data. Nó không tạo ra list 3 triệu phần tử ngay lập tức mà chỉ tạo khi cần.
•	Multiprocessing: Python có cơ chế GIL (Global Interpreter Lock) hạn chế đa luồng (threading) thực sự trên CPU. Do đó, để tận dụng đa nhân cho các tác vụ nặng về tính toán (CPU-bound) như xử lý văn bản, ta phải dùng ProcessPoolExecutor (đa tiến trình) thay vì ThreadPoolExecutor.

import numpy as np

# 1. Chuẩn hóa giá về khoảng [0, 1]
p = (prices - prices.min()) / (prices.max() - prices.min() + 1e-9)

# 2. Tạo trọng số (weights) ban đầu bằng cách bình phương giá
# Mục đích: Ưu tiên chọn các món hàng đắt tiền hơn (để cân bằng với số lượng hàng rẻ quá nhiều)
w = p**2

# 3. Điều chỉnh trọng số theo danh mục (Penalizing categories)
# Giảm khả năng được chọn của các danh mục đang bị thừa dữ liệu
w[categories == "Tools_and_Home_Improvement"] *= 0.5  # Giảm 50%
w[categories == "Automotive"] *= 0.05                 # Giảm 95% (vì Automotive quá nhiều)

# 4. Chuẩn hóa lại trọng số để tổng bằng 1 (yêu cầu của hàm numpy choice)
w = w / w.sum()

# 5. Thực hiện lấy mẫu dựa trên trọng số w
idx = np.random.choice(len(items), size=SIZE, replace=False, p=w)
sample = [items[i] for i in idx]
Giải thích logic:
•	p = w: Đây là phân phối xác suất. Món hàng nào có w cao thì khả năng hàm np.random.choice bốc trúng món đó càng cao.
•	replace=False: Đảm bảo một món hàng không được chọn 2 lần (không trùng lặp).

from concurrent.futures import ProcessPoolExecutor

# Tự động nhận diện số nhân CPU của máy tính
cpu_count = os.cpu_count()
WORKERS = max(cpu_count - 1, 1) # Chừa lại 1 nhân để máy không bị đơ

class ItemLoader:
    def load_in_parallel(self, workers):
        """
        Chia dữ liệu thành các 'chunk' (miếng nhỏ) và giao cho các nhân CPU xử lý cùng lúc.
        """
        with ProcessPoolExecutor(max_workers=workers) as pool:
            # map: Ánh xạ hàm xử lý vào từng chunk dữ liệu
            for batch in tqdm(pool.map(self.from_chunk, self.chunk_generator()), ...):
                results.extend(batch)
•	Ý nghĩa: Kỹ thuật này rất quan trọng khi làm Data Engineer. Nó tận dụng tối đa sức mạnh phần cứng để giảm thời gian xử lý dữ liệu từ hàng giờ xuống hàng phút.

A. MLOps: Model Drift (Sự trôi dạt mô hình)
Giảng viên nhắc đến "Model Drift". Đây là hiện tượng mô hình AI bị "lỗi thời" dù code không đổi.
•	Data Drift: Dữ liệu đầu vào thay đổi. Ví dụ: Trước đây sản phẩm Amazon chỉ bán sách, giờ bán cả đồ điện tử. Mô hình chỉ học bán sách sẽ đoán sai giá đồ điện tử.
•	Concept Drift: Mối quan hệ giữa Input và Output thay đổi. Ví dụ: Lạm phát làm giá cả tăng lên. Cùng một mô tả sản phẩm "Laptop 8GB RAM", năm 2020 giá $800, nhưng năm 2024 có thể giá khác.
•	Giải pháp: Phải có hệ thống Monitoring để phát hiện khi sai số (Metric) tăng cao, từ đó kích hoạt quy trình Retraining.
B. Batch API - Tại sao lại dùng cho Pre-processing?
Tại sao không dùng code Python (regex) để làm sạch mà phải tốn tiền dùng LLM?
•	Chất lượng: Regex không hiểu ngữ nghĩa. LLM có thể sửa lỗi chính tả, chuẩn hóa văn phong, loại bỏ câu marketing vô nghĩa ("Mua ngay kẻo lỡ") để giữ lại thông tin kỹ thuật thuần túy.
•	Chi phí: Sử dụng Batch Mode (như giảng viên đề cập) rẻ hơn 50% so với gọi API trực tiếp (Synchronous). Đây là cách duy nhất để xử lý 800.000 dòng dữ liệu với chi phí chấp nhận được cho một dự án cá nhân/học tập.

4. Kiến thức liên quan & Mở rộng
A. Groq vs. Traditional GPU
•	Trong bài giảng, giảng viên nhấn mạnh dùng Groq. Groq sử dụng kiến trúc chip LPU (Language Processing Unit) chuyên biệt cho suy luận (Inference), giúp tốc độ token/s nhanh gấp 10 lần GPU thường. Điều này cực kỳ hữu ích khi bạn cần test nhanh prompt trên dữ liệu mẫu.
B. Phân biệt Groq và Grok
•	Groq: Công ty phần cứng (Chip LPU), cung cấp API chạy Llama 3, Mixtral cực nhanh. Đây là cái chúng ta dùng.
•	Grok: Mô hình AI của xAI (Elon Musk) tích hợp trên X (Twitter).
•	Lưu ý: Đừng nhầm lẫn khi viết code hoặc chọn API Key.
C. Tại sao không dùng JSON Mode (Structured Outputs)?
Giảng viên có nhắc đến Structured Outputs (JSON).
•	Ưu điểm: Dễ dàng parse bằng code (json.loads()), đảm bảo không bao giờ sai format.
•	Nhược điểm: Tốn token (chi phí cao hơn) và xử lý chậm hơn một chút.
•	Quyết định: Trong bài toán Big Data này (800k items), sự đơn giản (Text Format) chiến thắng sự tiện lợi (JSON) để tối ưu chi phí. Tuy nhiên, trong môi trường Production cần độ tin cậy tuyệt đối, JSON Mode vẫn là lựa chọn số 1.
D. Batch Processing Architecture
Quy trình Batch thực tế mà bạn sẽ code (hoặc thấy trong các file sau):
1.	Prepare: Tạo file .jsonl (mỗi dòng là một request JSON).
2.	Upload: Upload file lên Server (Groq/OpenAI).
3.	Create Batch: Gửi lệnh "Xử lý file này cho tôi".
4.	Wait: Server xử lý (có thể mất 12-24h tùy nhà cung cấp, Groq thì nhanh hơn).
5.	Retrieve: Tải file kết quả .jsonl về và merge vào dataset chính.
Bước tiếp theo của bài học sẽ là giải pháp thay thế "0 đồng": Chạy model cục bộ (Local Model) cho những ai không muốn tốn tiền API.

4. Kiến thức liên quan & Mở rộng
A. JSON vs JSONL (JSON Lines)
•	JSON (.json): Toàn bộ dữ liệu là một object lớn. Phải load hết vào RAM mới đọc được. Nếu file 10GB -> Crash máy.
•	JSONL (.jsonl): Mỗi dòng là một object. Có thể đọc từng dòng (stream), xử lý xong dòng nào xóa dòng đó khỏi RAM. Đây là định dạng chuẩn cho Big Data và training LLM.
B. "Reasoning Tokens" là gì?
Trong bài, giảng viên thấy sự khác biệt về số lượng token output (48 vs 125).
•	Các model lớn hoặc được tinh chỉnh tốt thường có xu hướng "suy nghĩ" (reasoning/chain-of-thought) ngầm hoặc diễn giải chi tiết hơn để đảm bảo độ chính xác trước khi đưa ra kết quả cuối cùng.
•	Local model nhỏ (Llama 3.2) thường trả lời "cộc lốc" hoặc đi thẳng vào vấn đề (đôi khi sai format), dẫn đến số token ít hơn.
C. Chiến lược tiết kiệm chi phí (Cost Efficiency)
•	Batch Mode: Luôn giảm 50% chi phí so với gọi API trực tiếp.
•	Tại sao rẻ? Các nhà cung cấp cloud (OpenAI/Groq) có những lúc server rảnh rỗi (ví dụ: 3 giờ sáng). Batch request cho phép họ lấp đầy khoảng thời gian rảnh đó bằng các job không gấp (chấp nhận chờ 24h). Đó là lý do bạn được giảm giá.

A. Tại sao cần Baseline Model?

•	Generalization (Khái quát hóa): Là "chén thánh" của AI. Là khả năng mô hình học được các mẫu (patterns) chung từ dữ liệu train để áp dụng chính xác cho dữ liệu chưa từng gặp (unseen data).

o	Là khi mô hình học quá kỹ, nhớ cả những chi tiết nhiễu (noise) của tập train.
o	Biểu hiện: Điểm trên tập Train rất cao, nhưng điểm trên tập Validation/Test rất thấp.

6. Kiến thức liên quan & Mở rộng
1. Bag of Words (BoW) vs. Embeddings
•	Bag of Words (Dùng hôm nay): Chỉ đếm sự xuất hiện của từ. Nó không hiểu ngữ nghĩa.
o	Ví dụ: "good" và "great" là 2 từ hoàn toàn khác nhau, không liên quan gì nhau trong mắt mô hình.
•	Embeddings (Dùng cho LLM/Neural Network): Biến từ thành vector số trong không gian đa chiều.
o	Ví dụ: Vector của "good" sẽ nằm rất gần vector của "great".
o	Tại sao hôm nay dùng BoW? Vì nó đơn giản, nhanh và dễ hiểu (interpretable) cho một mô hình baseline.
2. Định lý "Dao cạo Occam" (Occam's Razor) trong AI
•	Nguyên lý: "Nếu hai giải pháp có kết quả tương đương nhau, hãy chọn giải pháp đơn giản hơn".
•	Nếu XGBoost đoán giá sai số $30 và LLM Fine-tuned đoán sai số $29.5 nhưng tốn chi phí gấp 1000 lần và chạy chậm gấp 100 lần -> Hãy chọn XGBoost.
3. Data Leakage trong Vectorization
•	Một lỗi sơ đẳng nhưng chết người: Gọi vectorizer.fit() trên toàn bộ dữ liệu (cả train và val).
•	Hậu quả: Mô hình sẽ biết trước "từ vựng" của tập kiểm tra, dẫn đến kết quả ảo.
•	Quy tắc: Chỉ fit trên Train, và chỉ transform trên Validation/Test.

import re
from sklearn.metrics import mean_squared_error, r2_score
import pandas as pd
import plotly.express as px
import plotly.graph_objects as go
from itertools import accumulate
import math
from tqdm.notebook import tqdm
from concurrent.futures import ThreadPoolExecutor

GREEN = "\033[92m"
YELLOW = "\033[93m"
RED = "\033[91m"
RESET = "\033[0m"
COLOR_MAP = {"red": RED, "orange": YELLOW, "green": GREEN}

WORKERS = 5
DEFAULT_SIZE = 200


class Tester:
    def __init__(self, predictor, data, title=None, size=DEFAULT_SIZE, workers=WORKERS):
        self.predictor = predictor
        self.data = data
        self.title = title or self.make_title(predictor)
        self.size = size
        self.titles = []
        self.guesses = []
        self.truths = []
        self.errors = []
        self.colors = []
        self.workers = workers

    @staticmethod
    def make_title(predictor) -> str:
        return predictor.__name__.replace("__", ".").replace("_", " ").title().replace("Gpt", "GPT")

    @staticmethod
    def post_process(value):
        if isinstance(value, str):
            value = value.replace("$", "").replace(",", "")
            match = re.search(r"[-+]?\d*\.\d+|\d+", value)
            return float(match.group()) if match else 0
        else:
            return value

    def color_for(self, error, truth):
        if error < 40 or error / truth < 0.2:
            return "green"
        elif error < 80 or error / truth < 0.4:
            return "orange"
        else:
            return "red"

    def run_datapoint(self, i):
        datapoint = self.data[i]
        value = self.predictor(datapoint)
        guess = self.post_process(value)
        truth = datapoint.price
        error = abs(guess - truth)
        color = self.color_for(error, truth)
        title = datapoint.title if len(datapoint.title) <= 40 else datapoint.title[:40] + "..."
        return title, guess, truth, error, color

    def chart(self, title):
        df = pd.DataFrame(
            {
                "truth": self.truths,
                "guess": self.guesses,
                "title": self.titles,
                "error": self.errors,
                "color": self.colors,
            }
        )

        # Pre-format hover text
        df["hover"] = [
            f"{t}\nGuess=${g:,.2f} Actual=${y:,.2f}"
            for t, g, y in zip(df["title"], df["guess"], df["truth"])
        ]

        max_val = float(max(df["truth"].max(), df["guess"].max()))

        fig = px.scatter(
            df,
            x="truth",
            y="guess",
            color="color",
            color_discrete_map={"green": "green", "orange": "orange", "red": "red"},
            title=title,
            labels={"truth": "Actual Price", "guess": "Predicted Price"},
            width=1000,
            height=800,
        )

        # Assign customdata per trace (one color/category = one trace)
        for tr in fig.data:
            mask = df["color"] == tr.name
            tr.customdata = df.loc[mask, ["hover"]].to_numpy()
            tr.hovertemplate = "%{customdata[0]}<extra></extra>"
            tr.marker.update(size=6)

        # Reference line y=x
        fig.add_trace(
            go.Scatter(
                x=[0, max_val],
                y=[0, max_val],
                mode="lines",
                line=dict(width=2, dash="dash", color="deepskyblue"),
                name="y = x",
                hoverinfo="skip",
                showlegend=False,
            )
        )

        fig.update_xaxes(range=[0, max_val])
        fig.update_yaxes(range=[0, max_val])
        fig.update_layout(showlegend=False)
        fig.show()

    def error_trend_chart(self):
        n = len(self.errors)

        # Running mean and std (pure Python)
        running_sums = list(accumulate(self.errors))
        x = list(range(1, n + 1))
        running_means = [s / i for s, i in zip(running_sums, x)]

        running_squares = list(accumulate(e * e for e in self.errors))
        running_stds = [
            math.sqrt((sq_sum / i) - (mean**2)) if i > 1 else 0
            for i, sq_sum, mean in zip(x, running_squares, running_means)
        ]

        # 95% confidence interval for mean
        ci = [1.96 * (sd / math.sqrt(i)) if i > 1 else 0 for i, sd in zip(x, running_stds)]
        upper = [m + c for m, c in zip(running_means, ci)]
        lower = [m - c for m, c in zip(running_means, ci)]

        # Plot
        fig = go.Figure()

        # Shaded confidence interval band
        fig.add_trace(
            go.Scatter(
                x=x + x[::-1],
                y=upper + lower[::-1],
                fill="toself",
                fillcolor="rgba(128,128,128,0.2)",
                line=dict(color="rgba(255,255,255,0)"),
                hoverinfo="skip",
                showlegend=False,
                name="95% CI",
            )
        )

        # Main line with hover text showing CI
        fig.add_trace(
            go.Scatter(
                x=x,
                y=running_means,
                mode="lines",
                line=dict(width=3, color="firebrick"),
                name="Cumulative Avg Error",
                customdata=list(
                    zip(
                        ci,
                    )
                ),
                hovertemplate=(
                    "n=%{x}<br>"
                    "Avg Error=$%{y:,.2f}<br>"
                    "±95% CI=$%{customdata[0]:,.2f}<extra></extra>"
                ),
            )
        )

        # Title with final stats
        final_mean = running_means[-1]
        final_ci = ci[-1]
        title = f"{self.title} Error: ${final_mean:,.2f} ± ${final_ci:,.2f}"

        fig.update_layout(
            title=title,
            xaxis_title="Number of Datapoints",
            yaxis_title="Average Absolute Error ($)",
            width=1000,
            height=360,
            template="plotly_white",
            showlegend=False,
        )

        fig.show()

    def report(self):
        average_error = sum(self.errors) / self.size
        mse = mean_squared_error(self.truths, self.guesses)
        r2 = r2_score(self.truths, self.guesses) * 100
        title = f"{self.title} results<br><b>Error:</b> ${average_error:,.2f} <b>MSE:</b> {mse:,.0f} <b>r²:</b> {r2:.1f}%"
        self.error_trend_chart()
        self.chart(title)

    def run(self):
        with ThreadPoolExecutor(max_workers=self.workers) as ex:
            for title, guess, truth, error, color in tqdm(
                ex.map(self.run_datapoint, range(self.size)), total=self.size
            ):
                self.titles.append(title)
                self.guesses.append(guess)
                self.truths.append(truth)
                self.errors.append(error)
                self.colors.append(color)
                print(f"{COLOR_MAP[color]}${error:.0f} ", end="")
        self.report()


def evaluate(function, data, size=DEFAULT_SIZE, workers=WORKERS):
    Tester(function, data, size=size, workers=workers).run()

•	Scikit-learn (sklearn): Thư viện tiêu chuẩn vàng cho Machine Learning tại Python. Nó cung cấp các công cụ nhất quán cho việc tiền xử lý dữ liệu, huấn luyện mô hình và đánh giá.
•	Khoảng tin cậy (Confidence Interval - Vùng xám trong biểu đồ):
o	Khi bạn tính sai số trung bình trên 200 mẫu, con số đó có thể là ngẫu nhiên.
o	Khoảng tin cậy 95% cho biết: "Chúng tôi tin chắc 95% rằng sai số thực sự nằm trong khoảng X đến Y". Dải màu xám càng hẹp thì độ tin cậy càng cao (thường đạt được khi tăng số lượng mẫu kiểm thử).
•	R-squared ($R^2$): Chỉ số đo mức độ mô hình giải thích được sự biến thiên của dữ liệu.
o	$R^2 = 1$: Dự đoán hoàn hảo.
o	$R^2 = 0$: Ngang bằng với việc luôn đoán giá trung bình.
o	$R^2 < 0$: Tệ hơn cả việc đoán trung bình (như Random Pricer trong bài này).

Python
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.linear_model import LinearRegression
import numpy as np

# 1. Chuẩn bị dữ liệu
# Lấy giá và văn bản tóm tắt từ tập train
prices = np.array([float(item.price) for item in train])
documents = [item.summary for item in train]

# 2. Khởi tạo CountVectorizer (Bộ đếm vector)
# max_features=2000: Chỉ quan tâm 2000 từ xuất hiện nhiều nhất (để giảm nhiễu và tăng tốc độ)
# stop_words='english': Loại bỏ các từ nối vô nghĩa (the, a, an...)
vectorizer = CountVectorizer(max_features=2000, stop_words='english')

# 3. Fit & Transform
# .fit_transform làm 2 việc:
# - Học danh sách 2000 từ vựng từ 'documents'
# - Biến đổi 'documents' thành ma trận số (Sparse Matrix)
X = vectorizer.fit_transform(documents)

# 4. Huấn luyện Linear Regression trên dữ liệu văn bản đã số hóa
regressor = LinearRegression()
regressor.fit(X, prices)

# 5. Hàm dự đoán (Pipeline cho Inference)
def natural_language_linear_regression_pricer(item):
    # CỰC KỲ QUAN TRỌNG: Chỉ dùng .transform(), KHÔNG dùng .fit()
    # Phải dùng đúng bộ từ điển đã học từ tập train
    x = vectorizer.transform([item.summary])
    
    # Dự đoán giá, nếu ra số âm thì lấy 0 (max(..., 0))
    prediction = regressor.predict(x)[0]
    return max(prediction, 0)

B. Quy trình huấn luyện Mạng nơ-ron (The 4 Steps of Training)
Giảng viên nhấn mạnh 4 bước kỹ thuật diễn ra lặp đi lặp lại trong quá trình training:
1.	Forward Pass (Lan truyền xuôi):
o	Đưa dữ liệu đầu vào (Input) qua mạng nơ-ron.
o	Mô hình tính toán và đưa ra dự đoán ($\hat{y}$).
2.	Loss Calculation (Tính toán mất mát):
o	So sánh giá dự đoán ($\hat{y}$) với giá thực tế ($y$ - Ground Truth).
o	Tính ra con số sai lệch (Loss/Error).
3.	Backward Pass (Lan truyền ngược):
o	Sử dụng giải tích (đạo hàm) để tính Gradient.
o	Mục đích: Tìm hiểu xem nếu thay đổi từng tham số (weight) một chút xíu thì sai số sẽ tăng hay giảm.
4.	Optimization (Tối ưu hóa):
o	Thực hiện một bước nhỏ (Step) để cập nhật lại các tham số theo hướng giảm thiểu sai số.
o	Thuật toán phổ biến: Stochastic Gradient Descent (SGD).
C. Siêu tham số (Hyperparameters)
Đây là các cài đặt cấu hình hệ thống, không phải là trọng số được mô hình tự học:
•	Batch Size: Số lượng dữ liệu được xử lý trong một lần tính toán (không đưa cả 800k dòng vào cùng lúc mà chia nhỏ ra).
•	Epochs (Kỷ nguyên): Số lần mô hình được học trọn vẹn toàn bộ tập dữ liệu.
•	Learning Rate (Tốc độ học): Kích thước của bước nhảy khi cập nhật tham số. Bước quá lớn có thể đi quá đà (không hội tụ), bước quá nhỏ thì học rất lâu.
•	Hyperparameter Optimization: Thực chất là quá trình thử nghiệm các tổ hợp khác nhau để tìm ra bộ thông số tốt nhất.

# Đây là phần logic cốt lõi được mô tả trong bài học

# 1. Siêu tham số (Hyperparameters) - Những cài đặt "bên ngoài"
epochs = 100          # Số lần học lại toàn bộ dữ liệu
learning_rate = 0.01  # Tốc độ cập nhật kiến thức

for epoch in range(epochs):
    for batch in dataloader: # Duyệt qua từng lô dữ liệu nhỏ
        
        # --- BƯỚC 1: FORWARD PASS (Lan truyền xuôi) ---
        # Đưa dữ liệu (x) vào mô hình để lấy dự đoán (y_pred)
        y_pred = model(batch_x)

        loss = criterion(y_pred, batch_y)
        
        # --- BƯỚC 3: BACKWARD PASS (Lan truyền ngược) ---
        # Tính toán gradient (đạo hàm) cho tất cả các tham số

        loss.backward()
        
        # --- BƯỚC 4: OPTIMIZATION (Tối ưu hóa) ---
        # Cập nhật trọng số của mô hình dựa trên gradient vừa tính
        # Đây là bước mô hình thực sự "học"
        optimizer.step()
        
        # Đặt lại gradient về 0 cho vòng lặp tiếp theo (đặc thù của PyTorch)
        optimizer.zero_grad()

5. Kiến thức liên quan & Mở rộng
A. Tại sao gọi là "Vanilla" Neural Network?
•	"Vanilla" (Vani) trong tiếng Anh thường ám chỉ sự cơ bản, nguyên bản, không có gì phức tạp thêm thắt.
•	Trong bài này, "Vanilla NN" (thường là Multi-Layer Perceptron - MLP) chỉ bao gồm các lớp kết nối đầy đủ (Fully Connected Layers), chưa có cơ chế Attention (như Transformer) hay tích chập (như CNN). Đây là bước đệm để hiểu trước khi sang các mô hình phức tạp.
B. Frontier Models vs. Fine-tuning (Teaser cho tuần sau)
•	Bài học kết thúc bằng việc so sánh với Frontier Models. Đây là các mô hình LLM đã được train trước (Pre-trained) với lượng dữ liệu khổng lồ.
•	Tuy nhiên, ở Day 4, chúng ta có thể chỉ đang dùng chúng ở chế độ Inference (hỏi và đáp) hoặc Few-shot prompting để định giá.
•	Fine-tuning (Tuần sau): Sẽ là bước đột phá khi ta áp dụng quy trình 4 bước huấn luyện ở trên vào chính các Frontier Models này (thông qua kỹ thuật như LoRA - Low Rank Adaptation được nhắc trong slide) để biến chúng thành chuyên gia định giá.

import torch.nn as nn

# Định nghĩa lớp NeuralNetwork kế thừa từ nn.Module của PyTorch
class NeuralNetwork(nn.Module):
    def __init__(self, input_size):
        super(NeuralNetwork, self).__init__()
        # Định nghĩa các lớp tuyến tính (Linear/Dense Layers)
        # Input size: Kích thước vector văn bản (ví dụ 2000 từ)
        # Output size: 128 nơ-ron ở lớp ẩn đầu tiên
        self.layer1 = nn.Linear(input_size, 128)
        self.layer2 = nn.Linear(128, 64)
        # ... (nhiều lớp ẩn ở giữa để tăng khả năng học sâu) ...
        self.layer8 = nn.Linear(64, 1) # Lớp cuối cùng trả về 1 số duy nhất (Giá tiền)
        
        # Hàm kích hoạt ReLU (giúp mô hình học được các tương quan phi tuyến tính)
        self.relu = nn.ReLU()

    # Hàm forward: Quy định luồng dữ liệu đi qua mạng
    def forward(self, x):
        # Dữ liệu đi qua lớp 1 -> qua ReLU -> qua lớp 2 -> ...
        output1 = self.relu(self.layer1(x))
        output2 = self.relu(self.layer2(output1))
        # ...
        output8 = self.layer8(output7)
        return output8 # Trả về giá dự đoán

4. Kiến thức liên quan & Mở rộng
•	Hashing Vectorizer vs. Count Vectorizer:
o	HashingVectorizer sử dụng thuật toán băm (hashing trick) để ánh xạ từ vựng vào các chỉ số cố định. Nó không cần lưu trữ từ điển trong bộ nhớ (stateless), nên rất phù hợp với dữ liệu lớn (streaming data) và tiết kiệm RAM. Tuy nhiên, nó có thể gặp vấn đề "đụng độ" (collision) - hai từ khác nhau có cùng mã hash18181818.
•	ReLU (Rectified Linear Unit):
o	Hàm kích hoạt phổ biến nhất cho các lớp ẩn. Công thức: $f(x) = max(0, x)$. Nó giúp giải quyết vấn đề biến mất đạo hàm (vanishing gradient) tốt hơn Sigmoid hay Tanh và tính toán rất nhanh.
•	Siêu tham số (Hyperparameters):
o	Là các thông số bạn phải cài đặt trước khi huấn luyện (như Learning Rate, Batch Size, Epochs) và không được mô hình tự học. Việc tìm ra bộ siêu tham số tốt nhất thường dựa vào "thử và sai" (Trial & Error)19191919.

162. Day 5 - When Fine-Tuning Frontier Models Fails & Building Deep Neural Networks 
Chào Hieu, cảm ơn bạn đã đồng hành đến ngày cuối cùng của Tuần 6.
Đây là một buổi học mang tính bước ngoặt về tư duy. Chúng ta bắt đầu với một sự "thất vọng" (Fine-tuning thất bại) nhưng kết thúc bằng một sự "cứu rỗi" (Redemption) với kỹ thuật Deep Learning chuyên sâu.
Dưới đây là tổng hợp chi tiết bài học Day 5 - When Fine-Tuning Frontier Models Fails & Building Deep Neural Networks.
________________________________________
1. Tóm tắt cốt lõi (Core Summary)
•	Thất bại của Fine-tuning Frontier Model: Việc Fine-tune một mô hình cực thông minh (như GPT-4o-mini) cho bài toán đoán giá sản phẩm đã không mang lại kết quả tốt hơn, thậm chí còn gây nhiễu. Bài học rút ra: Không nên Fine-tune Frontier Model để dạy "kiến thức" (knowledge) mà nó đã biết, chỉ nên dùng để dạy "hành vi" (behavior/format).
•	Tư duy R&D: Trong Data Science, kết quả xấu không phải là "lỗi" (bug), mà là một thông tin giá trị giúp loại bỏ hướng đi sai.
•	Deep Neural Network (DNN) nâng cao: Để cứu vãn tình thế, giảng viên giới thiệu một kiến trúc mạng nơ-ron chuyên nghiệp (Pro-grade) sử dụng kỹ thuật Residual Blocks (ResNet), cho phép huấn luyện mạng sâu hơn, ổn định hơn so với "Vanilla NN" của Day 4.
________________________________________
2. Nội dung chính
A. Tại sao Fine-tuning Frontier Model thất bại?
Chúng ta đã thử Fine-tune GPT-4o-mini (bản giả định GPT-4.1 Nano) với hy vọng nó đoán giá chuẩn hơn, nhưng kết quả lại trồi sụt thất thường.
•	Lý do: Frontier Model đã được học trên hàng trăm triệu đô la dữ liệu. Nó đã có "kiến thức thế giới" (World Knowledge) khổng lồ để hiểu sản phẩm là gì. Việc chúng ta đưa thêm vài nghìn ví dụ về giá chỉ như "muối bỏ bể", thậm chí tạo ra tiếng ồn (noise) khiến mô hình bị lệch lạc (overfitting) vào tập dữ liệu nhỏ đó thay vì dùng kiến thức tổng quát.
•	Khi nào NÊN Fine-tune Frontier Model?
1.	Style/Tone: Muốn mô hình nói chuyện theo giọng văn cụ thể (vd: cướp biển, luật sư).
2.	Format: Bắt buộc output ra định dạng JSON/XML đặc thù.
3.	Edge Cases: Xử lý các trường hợp ngoại lệ mà Prompting không giải quyết được.
4.	New Skill: Một kỹ năng mới lạ chưa từng có trong dữ liệu huấn luyện gốc.
B. Giới thiệu Deep Neural Network (DNN) với Residual Blocks
Để kết thúc tuần học với kết quả tích cực, giảng viên giới thiệu file deep_neural_network.py. Đây không còn là mạng nơ-ron "nhập môn" (Vanilla) nữa mà là kiến trúc hiện đại:
•	Deep: Mạng sâu hơn (có thể coi là 10 đến 50 lớp tùy cách đếm).
•	Residual Connections (Skip Connections): Kỹ thuật cho phép tín hiệu đi tắt qua các lớp, giúp tránh vấn đề biến mất đạo hàm (vanishing gradient) khi mạng quá sâu.
________________________________________
3. Kiến trúc & Quy trình (Pipeline)
Kiến trúc mạng DNN mới này được xây dựng dựa trên các khối Residual Block lặp lại:
Đoạn mã
graph TD
    Input --> Linear1
    Linear1 --> LayerNorm1
    LayerNorm1 --> ReLU1
    ReLU1 --> Dropout
    Dropout --> Linear2
    Linear2 --> LayerNorm2
    LayerNorm2 --> Sum((+))
    Input --> Sum
    Sum --> ReLU_Out --> Output
•	Giải thích: Dữ liệu đi qua các lớp xử lý (Linear, Norm...) nhưng đồng thời cũng có một đường "đi tắt" (Input --> Sum). Tại đầu ra, kết quả xử lý được cộng gộp với input ban đầu. Điều này giúp mô hình học được "sự thay đổi" (residual) thay vì phải học lại từ đầu, giúp hội tụ nhanh hơn và sâu hơn.
________________________________________
4. Phân tích Code (deep_neural_network.py)
Đây là file code quan trọng nhất, thể hiện trình độ "Pro" của kỹ sư AI.
A. Khối Residual Block (Trái tim của mạng)
Python
class ResidualBlock(nn.Module):
    def __init__(self, hidden_size, dropout_prob):
        super(ResidualBlock, self).__init__()
        # Chuỗi các lớp xử lý liên tiếp
        self.block = nn.Sequential(
            nn.Linear(hidden_size, hidden_size), # Lớp tuyến tính
            nn.LayerNorm(hidden_size),           # Chuẩn hóa để ổn định training
            nn.ReLU(),                           # Hàm kích hoạt
            nn.Dropout(dropout_prob),            # Ngẫu nhiên tắt nơ-ron để tránh học vẹt (Overfitting)
            nn.Linear(hidden_size, hidden_size),
            nn.LayerNorm(hidden_size),
        )
        self.relu = nn.ReLU()

    def forward(self, x):
        residual = x          # 1. Lưu lại giá trị input gốc (bản sao)
        out = self.block(x)   # 2. Cho input đi qua các lớp xử lý
        out += residual       # 3. KỸ THUẬT QUAN TRỌNG: Cộng input gốc vào kết quả (Skip Connection)
        return self.relu(out) # 4. Kích hoạt lần cuối
•	Ghi chú: Dòng out += residual chính là phép màu của ResNet (Microsoft Research), cho phép huấn luyện các mạng cực sâu mà không bị lỗi.
B. Mạng Deep Neural Network (DNN)
Python
class DeepNeuralNetwork(nn.Module):
    def __init__(self, input_size, num_layers=10, hidden_size=4096, dropout_prob=0.2):
        super(DeepNeuralNetwork, self).__init__()

        # Lớp đầu vào: Biến đổi vector đặc trưng thành vector ẩn (hidden size)
        self.input_layer = nn.Sequential(
            nn.Linear(input_size, hidden_size),
            nn.LayerNorm(hidden_size),
            nn.ReLU()
        )
        
        # Tạo chồng (stack) các Residual Blocks
        # ModuleList giúp PyTorch quản lý danh sách các layer này
        self.residual_blocks = nn.ModuleList([
            ResidualBlock(hidden_size, dropout_prob) for _ in range(num_layers)
        ])
        
        # Lớp đầu ra: Nén về 1 con số duy nhất (Giá tiền)
        self.output_layer = nn.Linear(hidden_size, 1)

    def forward(self, x):
        x = self.input_layer(x)
        for block in self.residual_blocks: # Đi qua từng block
            x = block(x)
        return self.output_layer(x)

5. Kiến thức liên quan & Mở rộng
•	Tại sao lại cần Residual (Skip Connection)?
o	Hãy tưởng tượng bạn chơi truyền tin (tam sao thất bản). Nếu hàng người quá dài (mạng quá sâu), thông tin từ người đầu đến người cuối sẽ bị sai lệch hoặc mất hẳn (vanishing gradient).
o	Skip Connection giống như việc người đầu tiên hét to thông tin gốc cho người cuối cùng nghe thấy, đảm bảo thông tin không bị mất đi qua các lớp trung gian.
•	Layer Normalization (LayerNorm): Kỹ thuật giúp chuẩn hóa dữ liệu đầu ra của từng lớp về dạng phân phối chuẩn, giúp mạng học ổn định hơn và cho phép dùng Learning Rate lớn hơn.
•	Dropout: Kỹ thuật "tắt ngẫu nhiên" một số nơ-ron trong quá trình train. Giống như việc bạn học bài nhưng thỉnh thoảng bịt một mắt lại, bắt buộc não bộ phải dùng các nơ-ron khác để bù đắp, từ đó mô hình trở nên "khỏe" (robust) hơn và tránh học tủ (overfitting).
