1 Kiến trúc Llama 3.2 3B

Llama 3.2 3B là mô hình của Meta với 3 tỷ tham số, tối ưu cho thiết bị biên. Dù nhỏ, nó thừa hưởng toàn bộ quy trình training từ Llama 405B thông qua Knowledge Distillation — nên thông minh hơn kích thước cho thấy.

Cấu trúc các lớp

LlamaForCausalLM ├── embed_tokens # vocab 128,256 → hidden 3,072 ├── layers (×28) # 28 Decoder Layers — "bộ não" chính │ ├── self_attn # Self-Attention │ │ ├── q_proj [3072 × 3072] # Query │ │ ├── k_proj [1024 × 3072] # Key (GQA — nhỏ hơn) │ │ ├── v_proj [1024 × 3072] # Value (GQA — nhỏ hơn) │ │ └── o_proj [3072 × 3072] # Output │ ├── mlp # Multi-Layer Perceptron │ │ ├── gate_proj [8192 × 3072] # SwiGLU gate │ │ ├── up_proj [8192 × 3072] │ │ └── down_proj [3072 × 8192] │ ├── input_layernorm # RMSNorm │ └── post_attention_layernorm ├── norm # Final RMSNorm └── lm_head # 3,072 → 128,256 (logits)

Embedding Layer: Chuyển token ID (số nguyên) thành vector dense 3,072 chiều mang ngữ nghĩa. Vocabulary size = 128,256 — lớn hơn Llama 2 (32k) giúp hiểu đa ngôn ngữ tốt hơn.

28 Decoder Layers — Self-Attention: Cho phép model "nhìn" toàn bộ câu để hiểu ngữ cảnh. k_proj và v_proj có chiều đầu ra 1,024 (không phải 3,072) — đây là Grouped Query Attention (GQA) giúp giảm bộ nhớ khi inference bằng cách chia sẻ Key/Value giữa nhiều Query heads.

MLP: "Phình" dữ liệu 3,072 → 8,192 để xử lý phi tuyến (SwiGLU activation), rồi nén về 3,072. Đây là nơi model lưu trữ "kiến thức thực tế" về thế giới.

RMSNorm: Chuẩn hóa dữ liệu trước mỗi sub-layer. Đơn giản hơn LayerNorm (bỏ qua phép tính mean) nhưng hiệu quả tương đương, ổn định gradient khi train.

Output Head: Chiếu 3,072 chiều → 128,256 logits. Mỗi số là score của token tương ứng; model chọn token có score cao nhất làm dự đoán tiếp theo.

2 Lý thuyết QLoRA

QLoRA = Quantization + Low-Rank Adaptation. Hai kỹ thuật giải quyết hai vấn đề độc lập: thiếu bộ nhớ (Q) và chi phí tính toán quá lớn (LoRA).

LoRA — Chỉ train phần nhỏ

Vấn đề: Full fine-tuning cập nhật 3 tỷ tham số — cần vài chục GB VRAM cho gradients + optimizer states.

Giải pháp:

  1. Freeze toàn bộ trọng số gốc W — không thay đổi, không tính gradient
  2. Thêm Adapter vào các lớp được chọn: hai ma trận nhỏ A và B
  3. Chỉ train A và B
∑
Công thức LoRA:
W_mới = W_gốc + ΔW = W_gốc + (A × B) × (alpha / r)

A: [d_out × r] — khởi tạo Gaussian  |  B: [r × d_in] — khởi tạo 0 (để ΔW = 0 lúc đầu)
Tại sao B = 0? Đảm bảo fine-tuning xuất phát chính xác từ hành vi base model, không thay đổi gì ngay lập tức.

Tính toán số tham số (r=32, chỉ attention layers)

r = 32
# Mỗi attention module trong 1 layer:
lora_q = 3072 * r + 3072 * r  # = 196,608 params
lora_k = 3072 * r + 1024 * r  # = 131,072 params
lora_v = 3072 * r + 1024 * r  # = 131,072 params
lora_o = 3072 * r + 3072 * r  # = 196,608 params

total_params = (lora_q + lora_k + lora_v + lora_o) * 28  # = ~18.3M
size_mb = (total_params * 4) / 1_000_000  # Float32 = 4 bytes
# Output: ~73 MB
# Thực tế trên HuggingFace: adapter_model.safetensors = 73.4 MB ✓
✓
Thêm ~18 triệu tham số mới (chỉ 0.6% so với 3 tỷ), nặng 73MB — đây là toàn bộ thứ cần lưu trữ và chia sẻ sau khi train. Nhỏ hơn nhiều ảnh RAW từ máy ảnh.

4-bit NF4 Quantization

4-bit thông thường chỉ lưu được 16 giá trị nguyên (0–15). NF4 (Normal Float 4) thông minh hơn: ánh xạ 16 giá trị theo phân phối chuẩn của trọng số neural network. Vì phần lớn trọng số nằm gần 0, NF4 phân bổ nhiều "điểm mô tả" hơn ở vùng này → giảm sai số lượng tử hóa.

Double Quantization: Nén thêm một lần nữa cả hằng số lượng tử hóa — tiết kiệm thêm ~0.37 bits/parameter.

quant_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_use_double_quant=True,       # Double quantization
    bnb_4bit_compute_dtype=torch.bfloat16, # Tính toán ở 16-bit cho nhanh
    bnb_4bit_quant_type="nf4"             # Normal Float 4
)
i
Chỉ base model bị nén 4-bit. Các LoRA adapter vẫn giữ float32/bfloat16 — vì đây là phần cần tính gradient chính xác. compute_dtype=bfloat16: khi tính toán (không phải lưu trữ), model tạm thời dequantize về bfloat16 để tính — đủ chính xác và nhanh hơn float32.

3 Luồng hoạt động QLoRA

3.1 Forward Pass khi Training

Input Prompt (text) │ ▼ Tokenizer Token IDs [batch × seq_len] │ ├──────────────────────────────────────────┐ │ │ ▼ Base Model — FROZEN, 4-bit ▼ LoRA Adapter — TRAINABLE, bf16 embed_tokens │ │ │ Layer 0..27: │ q_proj(4-bit) ────────────────────────────── + A_q × B_q × (α/r) k_proj(4-bit) v_proj(4-bit) ────────────────────────────── + A_v × B_v × (α/r) o_proj(4-bit) ────────────────────────────── + A_o × B_o × (α/r) gate/up/down ────────────────────────────── + A_mlp × B_mlp × (α/r) │ │ └───────────────── cộng gộp (+) ──────────┘ │ ▼ Output logits [vocab_size] │ ▼ Cross Entropy Loss (so với completion thực)

Điểm mấu chốt: Base model xử lý forward pass bình thường. Adapter tính song song và cộng kết quả vào. Đây là lý do LoRA không làm chậm inference — chỉ là một phép cộng thêm.

3.2 Bốn bước Training Loop

1
FORWARD PASS
Prompt → [Base Model 4-bit frozen] + [LoRA Adapters trainable] → Predicted tokens
↓
2
LOSS CALCULATION
Cross Entropy(predicted_tokens, completion_tokens). Ví dụ: model dự đoán "249" nhưng thực tế "199" → Loss cao
↓
3
BACKWARD PASS (Backpropagation)
Tính gradient CHỈ cho A và B — bỏ qua 3 tỷ params của base model. Tiết kiệm ~99.4% khối lượng tính toán.
↓
4
OPTIMIZATION (paged_adamw_32bit)
Cập nhật A và B theo hướng giảm Loss. Bước nhỏ theo learning rate hiện tại của Cosine Scheduler.

# 2. Gắn adapter vào base model (+73MB)

# 3. Predict
def model_predict(item):
    inputs = tokenizer(item["prompt"], return_tensors="pt").to("cuda")
    with torch.no_grad():  # Tắt gradient → giảm ~50% VRAM, tăng tốc
        output_ids = fine_tuned_model.generate(**inputs, max_new_tokens=8)
    prompt_len = inputs["input_ids"].shape[1]
    generated_ids = output_ids[0, prompt_len:]
    return tokenizer.decode(generated_ids)

max_new_tokens=8: Llama tokenizer mã hóa số 0–999 thành 1 token duy nhất. Giá dưới $1000 tối đa 3–4 tokens. Đặt 8 là an toàn.

Prompt Format & Rounding Strategy

def make_prompts(self, tokenizer, max_tokens, do_round):
    tokens = tokenizer.encode(self.summary, add_special_tokens=False)
    if len(tokens) > max_tokens:
        summary = tokenizer.decode(tokens[:max_tokens]).rstrip()  # Cắt
    else:
        summary = self.summary

    self.prompt = f"{QUESTION}\n\n{summary}\n\n{PREFIX}"
    self.completion = f"{round(self.price)}.00" if do_round else str(self.price)

5 Cấu hình Training

5.1 QLoRA Hyperparameters

LORA_R
64
Rank của ma trận adapter. Số càng lớn, adapter học được đặc trưng phức tạp hơn nhưng tốn VRAM. Light Mode dùng 32; Full Mode dùng 64.
LORA_ALPHA
128
Hệ số scaling. alpha/r = 2. ΔW thực tế = A×B × (128/64). Quy tắc ngón tay cái: alpha = 2×r cho kết quả ổn định.
LORA_DROPOUT
0.1
Tắt ngẫu nhiên 10% neurons mỗi bước train. Buộc model học đặc trưng độc lập → chống overfitting.
TARGET_MODULES
Attn + MLP
q/k/v/o_proj + gate/up/down_proj. Full Mode train cả attention lẫn MLP — attention học ngữ cảnh, MLP học kiến thức về giá.

5.2 Training Hyperparameters

EPOCHS
3
Số lần nhìn thấy toàn bộ 800k mẫu. Thực tế: Epoch 1–2 tốt, Epoch 3 overfitting. Checkpoint tốt nhất ở cuối Epoch 2.
Effective Batch
64
BATCH_SIZE=16 × GRADIENT_ACCUMULATION=4. GPU load 16 mẫu/lần, tích lũy gradient 4 bước rồi mới update → tương đương batch 64.
LEARNING_RATE
2e-4
Điểm khởi đầu chuẩn cho QLoRA (từ paper gốc Dettmers et al.). Kết hợp Cosine Scheduler để giảm dần về 0.
OPTIMIZER
paged_adamw
Adam + Weight Decay. "Paged": đẩy optimizer states sang CPU RAM khi GPU VRAM đầy → tránh OOM. weight_decay=0.001 là regularization nhẹ.

Cosine LR Scheduler với Warmup

train_parameters = SFTConfig(
    # ... các params khác ...
    learning_rate=2e-4,
    warmup_ratio=0.03,         # 3% bước đầu: LR tăng 0 → 2e-4 (tránh "sốc nhiệt")
    lr_scheduler_type="cosine", # Sau đó giảm theo hàm cosine về 0
    gradient_accumulation_steps=4,
    max_grad_norm=0.3,          # Gradient clipping — tránh explosion
    group_by_length=True,       # Nhóm mẫu cùng độ dài → giảm padding → nhanh hơn ~15%
    save_steps=200,
    save_total_limit=10,        # Chỉ giữ 10 checkpoint → tránh đầy đĩa
    eval_strategy="steps",
    push_to_hub=True,
)
