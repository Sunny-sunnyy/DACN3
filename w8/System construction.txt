1.	Góc nhìn OpenAI (Độc lập): Agent là hệ thống AI có thể thực hiện công việc thay bạn một cách độc lập (như một nhân viên ảo).
2.	Góc nhìn Anthropic (Kiểm soát quy trình): Agent là hệ thống mà LLM kiểm soát quy trình làm việc (Workflow). Thay vì code cứng nhắc (A -> B -> C), LLM tự quyết định làm A, B hay C dựa trên mục tiêu.
3.	Góc nhìn Tool Use & Loop (Vòng lặp công cụ): Agent là một LLM chạy trong một vòng lặp (loop), liên tục gọi các công cụ (Tools) cho đến khi đạt được mục tiêu đề ra.

Lưu ý: Bạn chưa cung cấp file code .py chi tiết của buổi này, nhưng trong file PDF Copy of LLMs Week 8 Day 1.pdf (Trang 9) có đoạn code mẫu quan trọng giới thiệu về Modal. Tôi sẽ phân tích đoạn này vì đây là công nghệ cốt lõi của bài học.
Code Snippet: Giới thiệu Modal (Trang 9 Slide)
Python
import modal

# 1. Khởi tạo ứng dụng Modal
# Đây là đối tượng đại diện cho ứng dụng của bạn trên Cloud
app = modal.App()

# 2. Định nghĩa hàm chạy trên Cloud (Serverless Function)
# Decorator @app.function() biến hàm Python thường thành hàm chạy trên hạ tầng của Modal
@app.function()
def hello():
    # Khi gọi hàm này, dòng print sẽ chạy trên máy chủ của Modal, không phải máy local
    print("Running remotely")
Giải thích logic:
1.	import modal: Thư viện Python để giao tiếp với nền tảng Modal.
2.	app = modal.App(): Tạo một namespace cho ứng dụng. Mọi container, image, và function sẽ được gắn vào app này.
3.	@app.function(): Đây là "phép thuật" của Modal. Bất kỳ hàm nào đặt dưới decorator này sẽ được đóng gói, đẩy lên cloud, chạy trong một container (có thể cấu hình RAM, CPU, GPU) và trả kết quả về máy bạn. Bạn không cần Dockerfile hay cấu hình Kubernetes phức tạp.
Mở rộng cho bài học hôm nay (Contextual Code):
Trong thực tế bài học, đoạn code sẽ phức tạp hơn để load mô hình Fine-tuned. Logic sẽ đại loại như sau (Mô phỏng):

image = modal.Image.debian_slim().pip_install("torch", "transformers") # Cài thư viện

@app.function(image=image, gpu="T4") # Yêu cầu GPU T4
def predict_price(description):
    # Load mô hình đã fine-tune từ Tuần 7
    model = load_model("path/to/fine_tuned_weights") 
    # Dự đoán giá
    price = model.generate(description)

5. Kiến thức liên quan & Mở rộng
A. Serverless AI vs. Traditional Server
•	Traditional (EC2, VPS): Bạn thuê 1 máy chủ GPU, trả tiền 24/7 dù có chạy hay không. Rất tốn kém cho các dự án cá nhân hoặc startup nhỏ.
•	Serverless (Modal, Lambda): Bạn chỉ trả tiền cho thời gian code thực sự chạy (tính theo giây). Với LLM, điều này cực kỳ lợi vì bạn chỉ tốn tiền GPU khi có người hỏi hoặc khi Agent cần xử lý tác vụ.
B. Agentic Workflow vs. Autonomous Agent
•	Agentic Workflow: Vẫn có sự tham gia của LLM, nhưng các bước được code cứng (Hard-coded orchestration). Ví dụ: Dùng LLM tóm tắt -> Dùng LLM dịch -> Lưu file.
•	Autonomous Agent: LLM tự quyết định các bước. Ví dụ: Prompt: "Hãy viết báo cáo thị trường". Agent tự nghĩ: "Mình cần search Google trước -> Đọc 3 bài báo -> Tóm tắt -> Viết báo cáo".
C. Ensemble Modeling (Mô hình tổ hợp)
Trong dự án này, giảng viên áp dụng kỹ thuật Ensemble: kết hợp kết quả của nhiều mô hình (Open Source Fine-tuned + Frontier Model) để đưa ra quyết định chính xác hơn. Đây là kỹ thuật thường thấy trong Machine Learning thi đấu (Kaggle) để tăng độ chính xác.
Kết luận: Bài học này là bước chuyển mình quan trọng từ việc "Biết train mô hình" (Tuần 7) sang "Biết biến mô hình thành sản phẩm thực tế" (Tuần 8) bằng cách sử dụng công nghệ Cloud hiện đại (Modal) và tư duy Agent.

4. Phân tích Code (Thiết lập Modal)
Dựa trên nội dung phiên âm, phần này chưa đi vào code Python cụ thể của Agent mà dừng lại ở việc thiết lập tài khoản Modal và mở trình soạn thảo Cursor. Tuy nhiên, dựa trên slide và ngữ cảnh, tôi giải thích cơ chế hoạt động của Modal mà bạn sắp code:
Cơ chế "Infrastructure as Code" của Modal:
Thay vì phải tạo file Docker, cấu hình Kubernetes, hay vào AWS Console bấm nút thuê máy chủ, Modal cho phép bạn làm điều đó ngay trong file Python:
Python
# (Code minh họa cơ chế hoạt động sắp tới)
import modal

# 1. Định nghĩa "App" - Đơn vị quản lý ứng dụng trên Cloud
app = modal.App("pricing-project")

# 2. Định nghĩa môi trường (Image) - Tương tự Dockerfile nhưng viết bằng Python
# Cài đặt sẵn các thư viện cần thiết
image = modal.Image.debian_slim().pip_install("torch", "transformers")

# 3. Định nghĩa Hàm Serverless
# @app.function: Biến hàm Python thường thành hàm chạy trên Cloud của Modal
# gpu="T4": Yêu cầu cấp GPU T4 khi chạy hàm này
@app.function(image=image, gpu="T4") 
def run_inference(data):
    # Code này chạy trên máy chủ Modal, tận dụng GPU
    print("Đang chạy trên Cloud...")
    return model.generate(data)

# 4. Chạy hàm từ máy local (local_entrypoint)
@app.local_entrypoint()
def main():
    # Gọi hàm trên cloud như gọi hàm thường
    result = run_inference.remote("Input data")
    print(result)
Ghi chú:
•	@app.function: Đây là decorator quan trọng nhất. Nó đóng gói code của bạn và đẩy lên server Modal.
•	.remote(): Lệnh để kích hoạt hàm chạy trên cloud từ máy tính cá nhân của bạn.

5. Kiến thức liên quan & Mở rộng
A. Tại sao "Build from Scratch" (Tự xây dựng) mà không dùng Framework?
Giảng viên nhắc đến Anthropic's Blog Post: "Building Effective Agents". Bài viết này khuyên rằng:

•	Khi mới học hoặc làm các dự án cụ thể, việc tự viết code gọi API (glue code) giúp bạn kiểm soát hoàn toàn luồng đi của dữ liệu, dễ debug và hiểu rõ "tại sao nó hoạt động".
B. Khái niệm "Ensemble" trong LLM
Trong Machine Learning cổ điển (như Random Forest), Ensemble là việc gộp kết quả của nhiều cây quyết định để có kết quả tốt hơn một cây lẻ.
Trong bài này, Ensemble Agent áp dụng tư duy tương tự:
•	Mô hình A (Fine-tuned): Giỏi về kiến thức tên miền hẹp (giá cả).
•	Mô hình B (Frontier + RAG): Giỏi về kiến thức tổng quát và tra cứu.
•	Kết hợp A + B = Độ tin cậy cao hơn.
C. Quy trình triển khai thực tế
Quy trình bạn sắp làm phản ánh đúng môi trường Production hiện đại:
1.	Dev trên máy local (VS Code/Cursor).
2.	Deploy logic xử lý nặng (AI Model) lên Serverless (Modal).
3.	Logic điều phối (Agent) gọi tới các endpoint Serverless đó.

import modal
from modal import Image

# 1. Định nghĩa App
app = modal.App("llama")

# 2. Định nghĩa Môi trường (Image)
# Cài đặt các thư viện Deep Learning cần thiết
image = Image.debian_slim().pip_install("torch", "transformers", "accelerate")

# 3. Kết nối với Secret đã tạo trên Dashboard
# Dòng này cực kỳ quan trọng: Nó giúp container có quyền truy cập HF_TOKEN

GPU = "T4" # Sử dụng GPU T4 (Giá rẻ, đủ dùng cho model 3B)
MODEL_NAME = "meta-llama/Llama-3.2-3B"

# 4. Hàm Inference
@app.function(image=image, secrets=secrets, gpu=GPU, timeout=1800)
def generate(prompt: str) -> str:
    from transformers import AutoTokenizer, AutoModelForCausalLM, set_seed

    # Load Tokenizer & Model từ Hugging Face
    tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME)
    # ... cấu hình padding ...
    model = AutoModelForCausalLM.from_pretrained(MODEL_NAME, device_map="auto")

    set_seed(42) # Cố định seed để kết quả nhất quán
    inputs = tokenizer.encode(prompt, return_tensors="pt").to("cuda")
    
    # Sinh văn bản (Inference)
    outputs = model.generate(inputs, max_new_tokens=5)
    return tokenizer.decode(outputs[0])

Python
import modal
from modal import Image

app = modal.App("pricer")

# Cài thêm 'bitsandbytes' (để chạy 4-bit) và 'peft' (để load LoRA)
image = Image.debian_slim().pip_install(
    "torch", "transformers", "bitsandbytes", "accelerate", "peft"
)
secrets = [modal.Secret.from_name("huggingface-secret")]

# Cấu hình đường dẫn tới Model đã Fine-tune trên Hugging Face
# Bạn nên thay HF_USER bằng tên của bạn nếu bạn đã push model ở Tuần 7
HF_USER = "ed-donner" 
RUN_NAME = "2025-11-28_18.47.07"
PROJECT_RUN_NAME = f"price-{RUN_NAME}"
FINETUNED_MODEL = f"{HF_USER}/{PROJECT_RUN_NAME}" 

@app.function(image=image, secrets=secrets, gpu="T4", timeout=1800)
def price(description: str) -> float:
    import re
    import torch
    from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig
    from peft import PeftModel # Thư viện để quản lý Adapter

    # ... Thiết lập Prompt Template giống hệt lúc Train ...

    # 1. Cấu hình Quantization (Nén 4-bit để chạy nhẹ hơn)
    quant_config = BitsAndBytesConfig(
        load_in_4bit=True,
        bnb_4bit_quant_type="nf4",
        # ...
    )

    # 2. Load Base Model trước
    base_model = AutoModelForCausalLM.from_pretrained(
        "meta-llama/Llama-3.2-3B", 
        quantization_config=quant_config, 
        device_map="auto"
    )

    # 3. Load Fine-tuned Adapter và gắn vào Base Model
    # Đây là bước biến model thường thành "Chuyên gia định giá"
    fine_tuned_model = PeftModel.from_pretrained(base_model, FINETUNED_MODEL)

    # 4. Chạy dự đoán (Inference)
    # ... Code tokenization ...
    outputs = fine_tuned_model.generate(**inputs, max_new_tokens=10)
    decoded_text = tokenizer.decode(outputs[0], skip_special_tokens=True)

    # 5. Trích xuất con số từ văn bản trả về (Regex)
    # Ví dụ: Model trả về "Price is $25.00", ta chỉ lấy 25.0
    match = re.search(r"Price is \$(\d+(?:\.\d+)?)", decoded_text)
    return float(match.group(1)) if match else 0.0

192. Day 1 - Deploying Fine-Tuned Models to Modal Cloud with Persistent Storage 
Chào bạn, chúng ta vừa hoàn thành một bước tiến lớn: từ việc chạy code "dùng một lần" (ephemeral) sang việc xây dựng một Dịch vụ (Service) thực thụ có khả năng chạy nhanh hơn, ổn định hơn và lưu trữ được trạng thái.
Dưới đây là tổng hợp nội dung bài học 192. Day 1 - Deploying Fine-Tuned Models to Modal Cloud with Persistent Storage.
________________________________________
1. Tóm tắt cốt lõi (Core Summary)
•	Vấn đề của bài trước: Chạy ephemeral (phù du) rất tốn thời gian (mất ~1 phút 20 giây) vì mỗi lần chạy, Modal phải khởi tạo lại container và tải lại Model (3GB+) từ Hugging Face.
•	Tầm quan trọng của Preprocessing: Dữ liệu đầu vào khi suy luận (Inference) phải có định dạng giống hệt dữ liệu lúc huấn luyện (Training). Nếu lúc train có tiêu đề, danh mục, thì lúc hỏi cũng nên format lại y hệt để mô hình hiểu rõ nhất.
•	Giải pháp nâng cấp:
1.	Deployment: Thay vì dùng modal run, ta dùng modal deploy để biến hàm thành một endpoint cố định trên cloud.
2.	Class-based Service: Chuyển từ viết hàm đơn lẻ sang viết Class. Điều này giúp tận dụng việc khởi tạo một lần (load model) và dùng lại nhiều lần.
3.	Persistent Storage (Volume): Sử dụng ổ cứng mạng (Volume) của Modal để lưu (cache) trọng số model. Lần sau khởi động lại, máy chỉ cần đọc từ ổ cứng (mất ~30s) thay vì tải từ mạng (mất >1 phút).
________________________________________
2. Nội dung chính & Quy trình tối ưu
A. Preprocessing (Tiền xử lý)
Giảng viên nhấn mạnh: "Treat your data at inference time the same way at training time".
•	Trước khi gửi text vào mô hình dự đoán giá, hãy chạy nó qua một hàm tiền xử lý (pre-processor) để thêm ngữ cảnh (Category, Title...) giống như cách bạn đã làm sạch dữ liệu ở Tuần 6.
•	Điều này giúp tăng độ ổn định và chính xác của kết quả.
B. Từ Ephemeral (Phù du) sang Deployment (Triển khai)
•	Ephemeral (modal run): Code chạy xong -> Container tắt -> Dữ liệu mất sạch. Lần sau chạy lại từ đầu.
•	Deployment (modal deploy):
o	Tạo ra một định danh (handle) trên Dashboard Modal.
o	Cho phép gọi từ xa thông qua tên ứng dụng (ví dụ: Pricer.remote("input")).
o	Container sẽ giữ trạng thái "Warm" (nóng) trong khoảng 2 phút. Nếu gọi lại trong thời gian này, kết quả trả về tức thì.
C. Khái niệm "Cold Start" và "Warm Start"
•	Cold Start (Khởi động lạnh): Khi không ai dùng, Modal tắt container. Khi có request mới, nó phải bật máy, cài thư viện, tải model -> Tốn thời gian.
•	Warm Start (Khởi động nóng): Container đang chạy sẵn, request đến là xử lý ngay -> Tức thì.
•	Volume Cache (Giải pháp trung gian): Nếu bị Cold Start, thay vì tải model từ Internet (chậm), ta gắn một ổ cứng ảo (modal.Volume) chứa sẵn model vào container -> Nhanh hơn đáng kể.

import modal

# 1. Định nghĩa Volume (Ổ cứng mạng) để lưu Cache
# Ổ cứng này tên là "hf-hub-cache", sẽ tồn tại vĩnh viễn trên tài khoản Modal của bạn
cache_volume = modal.Volume.from_name("hf-hub-cache", create_if_missing=True)

@app.cls(  # Sử dụng @app.cls thay vì @app.function
    image=image, 
    secrets=secrets, 
    gpu=GPU, 
    timeout=1800,
    # Gắn ổ cứng vào thư mục /cache trong container
    volumes={"/cache": cache_volume} 
)
class Pricer:
    # 2. Hàm __enter__ (hoặc __init__): Chạy 1 lần khi container khởi động
    @modal.enter()
    def enter(self):
        # Load Model và lưu vào biến self (RAM)
        # Nhờ có Volume mounted tại /cache, Hugging Face sẽ tìm model ở đây trước khi tải từ mạng.
        self.tokenizer = AutoTokenizer.from_pretrained(BASE_MODEL, cache_dir="/cache")
        self.fine_tuned_model = PeftModel.from_pretrained(..., cache_dir="/cache")

    # 3. Hàm gọi thực thi
    @modal.method()
    def price(self, description: str) -> float:
        # Lúc này Model đã có sẵn trong RAM (self.fine_tuned_model), chỉ việc chạy
        outputs = self.fine_tuned_model.generate(...)
        return price
Tại sao pricer_service2.py tốt hơn?

2.	Modal Volume:
o	Lần đầu tiên chạy: Tải model từ Internet -> Lưu vào /cache (Volume).
o	Lần thứ 2 trở đi (kể cả khi Cold Start): Đọc model từ /cache (Local disk speed) -> Nhanh hơn nhiều.

4. Kiến thức thực tế (Pro Tips)
1. Cơ chế ngủ đông (Idle Timeout)
•	Mặc định, nếu không có request trong 2 phút, Modal sẽ tắt container (thu hồi GPU) để tiết kiệm tiền cho bạn.
•	Khi bạn gọi lại sau 5 phút, bạn sẽ gặp Cold Start (mất ~30s với phiên bản có Volume).
2. Giữ Container luôn sống (Keep Warm) - Tốn tiền hơn

import logging

class Agent:
    """
    Lớp trừu tượng (Abstract superclass) cho tất cả các Agent.

    GREEN = '\033[32m'

#### B. `specialist_agent.py` - Tác nhân chuyên gia

Đây là nơi "ma thuật" kết nối giữa Local và Cloud diễn ra.

```python
import modal
from agents.agent import Agent

# Kế thừa từ lớp Agent để có tính năng log màu
class SpecialistAgent(Agent):
    """
    Agent này chịu trách nhiệm chạy mô hình Fine-tuned của chúng ta trên Modal.
    """

    name = "Specialist Agent"
    color = Agent.RED  # Gán màu ĐỎ đặc trưng cho chuyên gia này

    def __init__(self):
        """
        Khởi tạo kết nối tới Modal.
        """
        self.log("Specialist Agent is initializing - connecting to modal")
        
        # QUAN TRỌNG: Kết nối tới Service đã Deploy ở bài trước.
        # "pricer-service": Tên App trên Modal Dashboard.
        # "Pricer": Tên Class trong code service (pricer_service2.py).
        Pricer = modal.Cls.from_name("pricer-service", "Pricer")
        
        # Tạo một instance (đối tượng) đại diện cho dịch vụ trên mây
        self.pricer = Pricer()

    def price(self, description: str) -> float:
        """
        Thực hiện cuộc gọi từ xa (Remote Call)
        """
        self.log("Specialist Agent is calling remote fine-tuned model")
        
        # .remote(): Lệnh này gửi data lên cloud, chạy hàm price() ở đó, và đợi kết quả trả về.
        # Đây là cơ chế RPC (Remote Procedure Call).
        result = self.pricer.price.remote(description)
        
        self.log(f"Specialist Agent completed - predicting ${result:.2f}")
        return result

```

**Logic hoạt động:**

1. Khi bạn gọi `agent = SpecialistAgent()`, nó không tải Model về máy bạn (Model nặng 3GB+). Nó chỉ tạo một "cái điều khiển từ xa" (`self.pricer`) trỏ tới Modal.
2. Khi bạn gọi `agent.price("iPhone")`, nó bấm nút trên điều khiển -> Tín hiệu bay lên Modal -> Modal xử lý -> Trả số tiền về.

### 4. Kiến thức liên quan & Mở rộng

#### 1. Proxy / Facade Pattern

Cách thiết kế `SpecialistAgent` này là một ví dụ của mẫu thiết kế **Facade** (Mặt tiền) hoặc **Proxy**.

* **Người dùng (User/Main Loop):** Chỉ cần biết `agent.price()`. Không cần biết bên dưới là Modal, AWS, hay chạy local.
* **Lợi ích:** Sau này nếu bạn muốn chuyển từ Modal sang chạy trên máy server riêng, bạn chỉ cần sửa code trong `SpecialistAgent`, các phần khác của hệ thống không bị ảnh hưởng.

#### 2. Latency (Độ trễ) trong hệ thống Agent

* Trong demo, lần đầu chạy mất ~30s (Cold Start), lần sau mất <1s (Warm Start).
* Khi thiết kế hệ thống nhiều Agent (Multi-Agent System), **độ trễ cộng dồn** là vấn đề lớn. Nếu Agent A chờ Agent B, Agent B lại bị Cold Start, cả hệ thống sẽ bị chậm.
* *Lưu ý:* Việc dùng `keep_warm` (như đã học bài trước) là cần thiết cho Production.

#### 3. Tại sao cần Class `Agent` đơn giản vậy?

Bạn có thể thắc mắc sao không dùng `print()` cho nhanh?

* Khi hệ thống chạy 4-5 Agent song song (Scanner quét, Planner lập kế hoạch, Messenger gửi tin...), terminal sẽ loạn xạ.
* Việc định danh `[Tên Agent]` và màu sắc giúp bạn debug nhanh hơn gấp 10 lần: "À, dòng màu đỏ bị lỗi -> Lỗi do ông Specialist, không phải ông Planner".

3.	Generation (Sinh câu trả lời):

o	Output: Giá dự đoán.

class EnsembleAgent(Agent):

        price3 = self.neural.price(description)

Chúng ta có 800.000 sản phẩm đã được chuyển thành vectors 384 chiều (dimensions). Con người không thể nhìn thấy không gian 384 chiều. Vì vậy, chúng ta dùng thuật toán t-SNE để "ép" không gian đó xuống còn 2 chiều (2D) hoặc 3 chiều (3D) để vẽ lên biểu đồ.
Quy trình thực hiện:
1.	Lấy mẫu (Sampling): Chỉ lấy 10.000 điểm dữ liệu (vì vẽ hết 800k điểm sẽ làm treo máy tính).
2.	Giảm chiều dữ liệu: Dùng t-SNE chuyển đổi từ $R^{384} \rightarrow R^2$ (hoặc $R^3$).
3.	Tô màu (Coloring): Dựa trên danh mục sản phẩm (ví dụ: Đồ chơi, Phụ tùng ô tô...) để xem chúng phân bố thế nào.
Phân tích biểu đồ (Insight từ Transcript):

o	Lý do: Đó là "Toy car parts" (Phụ tùng cho xe đồ chơi).
o	Ý nghĩa: Model all-MiniLM-L6-v2 hiểu ngữ nghĩa rất sâu. Nó hiểu rằng "phụ tùng xe đồ chơi" có tính chất kỹ thuật giống "phụ tùng xe thật" nên đặt chúng gần nhau, dù danh mục gốc là "Đồ chơi".

    def __init__(self, collection):
        # 1. Khởi tạo các chuyên gia con
        self.frontier_rag = FrontierAgent(collection) # RAG Model
        self.specialist = SpecialistAgent()           # Fine-tuned Model (Remote)
        # self.neural_net = NeuralNetworkAgent()      # (Tuỳ chọn nếu có file weights)

        # 2. Lấy ý kiến từ các chuyên gia
        # Giá từ RAG (Mạnh nhất)
        p1 = self.frontier_rag.price(description) 
        
        # Giá từ Specialist (Dự phòng)
        p2 = self.specialist.price(description)
        
        # Giá từ NN (Tham khảo thêm)
        # p3 = self.neural_net.price(description) 
        # Giả sử trong bài học rút gọn, ta chỉ demo với p3 giả lập hoặc bỏ qua nếu file quá nặng
        
        # 3. Tính toán kết quả hợp nhất (Weighted Average)
        # Công thức: 80% RAG + 10% Specialist + 10% NN
        # Nếu chỉ có 2 model, có thể điều chỉnh: 90% RAG + 10% Specialist
        
        final_price = (0.8 * p1) + (0.2 * p2) 
        
        self.log(f"Ensemble Logic: 0.8*{p1} + 0.2*{p2} = {final_price}")

from agents.agent import Agent
from agents.specialist_agent import SpecialistAgent
from agents.frontier_agent import FrontierAgent
from agents.neural_network_agent import NeuralNetworkAgent
from agents.preprocessor import Preprocessor

class EnsembleAgent(Agent):
    name = "Ensemble Agent"
    color = Agent.YELLOW  # Màu vàng để dễ nhận diện trong log

    def __init__(self, collection):
        """
        Khởi tạo Ensemble Agent bằng cách tạo ra các instance của 3 mô hình con.
        Lưu ý: Nếu máy yếu hoặc lỗi kỹ thuật, bạn có thể comment bớt các dòng khởi tạo ở đây.
        """
        self.log("Initializing Ensemble Agent")
        
        # 1. Khởi tạo Specialist (Fine-tuned Model trên Cloud)
        self.specialist = SpecialistAgent()
        
        # 2. Khởi tạo Frontier (RAG Model - Cần truyền collection ChromaDB vào)
        self.frontier = FrontierAgent(collection)
        
        # 3. Khởi tạo Neural Network (Model chạy local - Khá nặng)
        self.neural_network = NeuralNetworkAgent()
        
        # 4. Bộ tiền xử lý văn bản
        self.preprocessor = Preprocessor()
        self.log("Ensemble Agent is ready")

    def price(self, description: str) -> float:
        """
        Hàm thực thi chính:
        1. Tiền xử lý văn bản.
        2. Hỏi giá từ 3 chuyên gia.
        3. Tính trung bình có trọng số (Weighted Average).
        """
        self.log("Running Ensemble Agent - preprocessing text")
        
        # Bước 1: Chuẩn hóa đầu vào (quan trọng để các model hiểu giống nhau)
        rewrite = self.preprocessor.preprocess(description)
        self.log(f"Pre-processed text using {self.preprocessor.model_name}")

        # Bước 2: Gọi các Agent con (Agent Workflow)
        specialist = self.specialist.price(rewrite)      # Giá từ Fine-tuned
        frontier = self.frontier.price(rewrite)          # Giá từ RAG
        neural_network = self.neural_network.price(rewrite) # Giá từ NN

        # Bước 3: Áp dụng công thức Ensemble
        # 80% RAG + 10% Fine-tuned + 10% NN
        combined = frontier * 0.8 + specialist * 0.1 + neural_network * 0.1
        
        self.log(f"Ensemble Agent complete - returning ${combined:.2f}")
        return combined

199. Day 3 - Structured Outputs with Pydantic and Constrained Decoding 
Chào mừng bạn đến với ngày thứ 3 của tuần cuối cùng! Hôm nay chúng ta sẽ khám phá Structured Outputs (Đầu ra có cấu trúc) - một kỹ năng thiết yếu để biến các mô hình ngôn ngữ (vốn mơ hồ) thành các thành phần phần mềm đáng tin cậy.
Dựa vào bản phiên âm và slide Copy of LLMs Week 8 Day 3.pdf bạn cung cấp, đây là nội dung chi tiết:
1. Tóm tắt cốt lõi (Core Summary)
Bài học tập trung vào việc sử dụng Structured Outputs (thông qua thư viện Pydantic) để buộc LLM trả về dữ liệu có định dạng chuẩn (thường là JSON) thay vì văn bản tự do. Điểm nhấn đặc biệt là kỹ thuật Constrained Decoding (Giải mã có ràng buộc) giúp đảm bảo 100% kết quả đầu ra tuân thủ đúng cấu trúc đã định nghĩa, loại bỏ hoàn toàn việc "hallucinations" về cú pháp.
2. Nội dung chính
A. Tại sao cần Structured Outputs?
•	Vấn đề: Khi bạn hỏi LLM "Giá của iPhone 16 là bao nhiêu?", nó có thể trả lời "Giá là $1000", hoặc "$1000 nhé", hoặc "Khoảng một ngàn đô". Việc viết code (Regex) để trích xuất số $1000 từ các câu trả lời này rất mệt mỏi và dễ lỗi.
•	Giải pháp: Structured Outputs buộc LLM trả về một đối tượng (Object) duy nhất, ví dụ: {"price": 1000, "currency": "USD"}. Điều này giúp tích hợp LLM vào hệ thống phần mềm dễ dàng như gọi một hàm Python bình thường.
•	Ứng dụng trong bài học: Chúng ta sẽ dùng kỹ thuật này cho Scanner Agent để phân tích (parse) dữ liệu thô từ RSS feed thành các đối tượng Deal có cấu trúc rõ ràng.
B. Cơ chế hoạt động (The "Magic" behind)
Giảng viên giải thích hai lớp cơ chế:
1.	Lớp "Cảm giác" (Developer Experience):
o	Bạn định nghĩa một class Python kế thừa từ Pydantic BaseModel.
o	Bạn yêu cầu OpenAI trả về instance của class đó.
o	Bạn nhận lại một object Python hoàn chỉnh.
2.	Lớp "Thực tế" (Under the Hood):
*
o	Class Pydantic được chuyển đổi thành JSON Schema.
o	Schema này được đưa vào System Prompt của LLM.
o	LLM sinh ra chuỗi JSON khớp với Schema.
o	Thư viện OpenAI tự động parse chuỗi JSON đó ngược lại thành object Python.
C. Kỹ thuật Constrained Decoding (Giải mã ràng buộc)
Đây là "bí thuật" giúp OpenAI đảm bảo độ chính xác 100%:
•	Khi LLM dự đoán token tiếp theo, thay vì chọn tự do trong hàng ngàn từ vựng, hệ thống sẽ loại bỏ (masking) tất cả các token không hợp lệ theo Schema.
•	Ví dụ: Nếu Schema yêu cầu trường price là số (Integer), thì sau khi sinh token "price": , hệ thống sẽ chặn tất cả các token là chữ cái, chỉ cho phép sinh các token số (0-9).
•	Kết quả: LLM không thể sinh ra sai cú pháp dù nó muốn.
3. Kiến trúc & Quy trình thực hiện
Quy trình Scanner Agent với Structured Outputs:
1.	Define (Định nghĩa):
Python
from pydantic import BaseModel

class ProductDeal(BaseModel):
    product_name: str
    price: float
    currency: str
    merchant: str
2.	Prompting:
Gửi văn bản thô (Unstructured Text) từ RSS Feed + Yêu cầu response_format=ProductDeal.
3.	Parsing (Tự động):
OpenAI trả về object ProductDeal(product_name="iPhone 16", price=999.0, ...) thay vì chuỗi string.
4. Kiến thức mở rộng
•	Pydantic: Thư viện validation dữ liệu phổ biến nhất trong Python hiện nay.
•	Inference Time Constrained Decoding: Kỹ thuật này không chỉ dùng cho JSON mà còn dùng cho Code Generation (đảm bảo code đúng cú pháp) hoặc Grammar Constrained Generation (trong các thư viện như llama-cpp-python).
Bài học này là bước chuẩn bị quan trọng để xây dựng Scanner Agent - thành phần đầu tiên trong chuỗi xử lý tự động của hệ thống "The Price Is Right". Chúng ta sẽ áp dụng ngay kỹ thuật này trong phần thực hành tiếp theo!

1. Tóm tắt cốt lõi (Core Summary)
Bài học này nhấn mạnh sự đột phá về mặt thương mại của việc sử dụng LLM để phân tích dữ liệu phi cấu trúc (Unstructured Data Parsing), biến một vấn đề "hóc búa" trong quá khứ thành một giải pháp đơn giản và hiệu quả.

2. Nội dung chính
A. Sự đột phá của Intelligent Parsing (Phân tích cú pháp thông minh)
•	Vấn đề cũ: Trước đây, viết code để hiểu câu "Thường giá $200, nhưng tuần này giảm $50" là cực khó. Nếu định dạng thay đổi một chút, code sẽ lỗi (brittle parsers).
•	Giải pháp LLM: LLM hiểu ngữ nghĩa. Nó biết "giảm $50 từ $200" nghĩa là giá cuối cùng là $150.
•	Giá trị: Structured Outputs biến LLM thành một công cụ ETL (Extract - Transform - Load) cực mạnh, có thể ứng dụng ngay vào việc phân tích hồ sơ (CV), hóa đơn, hoặc tin tức thị trường với độ chính xác cao.
B. Scanner Agent: Hoàn thiện

import os
import requests
from litellm import completion # Dùng litellm để gọi Claude dễ dàng
from agents.agent import Agent

class MessagingAgent(Agent):
    name = "Messaging Agent"
    color = Agent.WHITE
    MODEL = "claude-sonnet-4-5" # Dùng model ngôn ngữ tự nhiên tốt để viết văn hay

    def __init__(self):
        # Lấy Key từ biến môi trường (File .env)
        self.pushover_user = os.getenv("PUSHOVER_USER")
        self.pushover_token = os.getenv("PUSHOVER_TOKEN")

    def craft_message(self, description, deal_price, estimated_true_value):
        """Dùng LLM để biến thông số khô khan thành lời quảng cáo hấp dẫn"""
        user_prompt = f"""
        Hãy tóm tắt deal này thành 2-3 câu thông báo đẩy hấp dẫn:
        Mô tả: {description}
        Giá bán: {deal_price}
        Giá trị thực ước tính: {estimated_true_value}
        """
        response = completion(model=self.MODEL, messages=[{"role": "user", "content": user_prompt}])
        return response.choices[0].message.content

    def push(self, text):
        """Gửi tin nhắn qua Pushover API"""
        payload = {
            "user": self.pushover_user,
            "token": self.pushover_token,
            "message": text,
            "sound": "cashregister", # Âm thanh tiền rơi!
        }
        requests.post("https://api.pushover.net/1/messages.json", data=payload)

    def notify(self, description, deal_price, estimated_true_value, url):
        # 1. Soạn tin nhắn
        hype_msg = self.craft_message(description, deal_price, estimated_true_value)
        # 2. Gửi đi
        final_msg = f"{hype_msg}\nLink: {url}"
        self.push(final_msg)

from agents.agent import Agent
from agents.specialist_agent import SpecialistAgent

from agents.neural_network_agent import NeuralNetworkAgent

class EnsembleAgent(Agent):
    name = "Ensemble Agent"

    def __init__(self, collection):
        """
        Khởi tạo 'Hội đồng chuyên gia'.
        Planning Agent không cần biết việc này, chỉ cần khởi tạo EnsembleAgent.
        """
        self.log("Initializing Ensemble Agent")
        self.specialist = SpecialistAgent() # Model nguồn mở đã fine-tune
        self.frontier = FrontierAgent(collection) # Model mạnh nhất (GPT-5) + RAG
        self.neural_network = NeuralNetworkAgent() # Mạng nơ-ron thuần túy
        self.preprocessor = Preprocessor() # Làm sạch dữ liệu đầu vào

    def price(self, description: str) -> float:
        """
        Hàm 'price' là interface chính (Tool) mà Planning Agent sẽ gọi.
        Mục đích: Trả về mức giá ước tính trung bình.
        """
        self.log("Running Ensemble Agent - preprocessing text")
        rewrite = self.preprocessor.preprocess(description)
        
        # Gọi song song 3 chuyên gia
        specialist = self.specialist.price(rewrite)
        frontier = self.frontier.price(rewrite)
        neural_network = self.neural_network.price(rewrite)
        
        # Công thức tính giá trung bình có trọng số (Weighted Average)
        # Frontier (RAG) chiếm 80% trọng số vì độ tin cậy cao
        combined = frontier * 0.8 + specialist * 0.1 + neural_network * 0.1
        self.log(f"Ensemble Agent complete - returning ${combined}")
        return combined

C. Vòng lặp Tự chủ (The Agent Loop) - QUAN TRỌNG NHẤT
Đây là đoạn code biến mô hình ngôn ngữ thành một Agent tự hành.
Python
    def plan(self, memory: List[str] = []) -> Optional[Opportunity]:
        """
        Chạy quy trình làm việc đầy đủ (Full Workflow).
        """
        self.log("Autonomous Planning Agent is kicking off a run")
        messages = self.messages[:] # Load lịch sử hội thoại/System prompt
        done = False # Cờ kiểm soát vòng lặp

        # VÒNG LẶP CHÍNH (THE LOOP)
        while not done:
            # 1. Gửi tin nhắn + Danh sách công cụ (tools) lên OpenAI
            response = self.openai.chat.completions.create(
                model=self.MODEL, messages=messages, tools=self.get_tools()
            )
            
            # 2. Kiểm tra xem LLM có muốn dùng công cụ không?
            if response.choices[0].finish_reason == "tool_calls":
                message = response.choices[0].message
                
                # 3. Thực thi công cụ (Hàm handle_tool_call sẽ tìm và chạy hàm tương ứng)
                # Lưu ý: Trong code thực tế, ta dùng mapping dictionary thay vì globals() để an toàn hơn
                results = self.handle_tool_call(message)
                
                # 4. Cập nhật bộ nhớ: Thêm yêu cầu của LLM và kết quả công cụ vào lịch sử
                messages.append(message)
                messages.extend(results)
                # Vòng lặp tiếp tục để LLM suy nghĩ tiếp dựa trên kết quả mới
            else:
                # Nếu LLM không gọi công cụ nữa (trả về text bình thường) -> Xong việc
                done = True
        
        reply = response.choices[0].message.content
        self.log(f"Autonomous Planning Agent completed with: {reply}")
        return self.opportunity

5. Kiến thức liên quan & mở rộng
•	ReAct Pattern (Reason + Act): Kiến trúc này thực chất là một biến thể của ReAct. LLM Suy luận ("Tôi cần quét web"), Hành động (Gọi tool Scanner), Quan sát (Nhận JSON từ Scanner), và lặp lại quá trình này.
•	Token Consumption (Tiêu thụ Token): Một vấn đề cần lưu ý trong vòng lặp này là chi phí. Mỗi lần lặp lại, toàn bộ lịch sử (System prompt + Tool calls trước đó + Kết quả tool) đều được gửi lại cho LLM. Với GPT-4 hoặc GPT-5, chi phí có thể tăng nhanh nếu vòng lặp quá dài.
•	Latency (Độ trễ): Như trong transcript giáo viên đề cập, việc khởi động Specialist Agent trên Modal tốn khoảng 30s (cold start), và quá trình chạy toàn bộ hệ thống có thể mất vài phút. Đây là đặc điểm của các hệ thống Agent phức tạp (Multi-step reasoning).
•	Sự khác biệt giữa Hard-coded vs Agentic:
o	Hard-coded (Workflow): Scanner -> for each deal -> Ensemble -> if cheap -> Notify. Nếu Scanner trả về lỗi hoặc định dạng lạ, code sẽ crash.
o	Agentic: Nếu Scanner không trả về deal nào, Planning Agent (LLM) có thể tự quyết định: "Không tìm thấy gì, tôi sẽ thử lại sau" hoặc "Tôi sẽ báo cho người dùng là hôm nay không có deal", thay vì crash hệ thống.
Tổng kết: Bạn vừa hoàn thành việc xây dựng một hệ thống AI cấp độ cao. Nó không chỉ trả lời câu hỏi, mà còn chủ động sử dụng các "giác quan" (Scanner), "bộ não phụ" (Ensemble) và "miệng" (Messaging) để thực hiện một công việc trọn vẹn.

•	Giải pháp thực tế: Trong môi trường Production, các kỹ sư sẽ chuyển sang chạy bất đồng bộ (Async). Ví dụ: Định giá 5 sản phẩm cùng một lúc (Parallel execution) thay vì từng cái một, giúp giảm thời gian chờ đợi xuống chỉ bằng thời gian của 1 sản phẩm.

from typing import Optional, List, Dict
from agents.agent import Agent
# ... imports khác ...

class AutonomousPlanningAgent(Agent):
    name = "Autonomous Planning Agent"
    MODEL = "gpt-5.1" # Sử dụng model thông minh nhất để lập kế hoạch

    def __init__(self, collection):
        # ... Khởi tạo các sub-agents ...
        self.memory = None # Khởi tạo biến bộ nhớ

    # --- CÔNG CỤ 1: QUÉT (CÓ BỘ NHỚ) ---
    def scan_the_internet_for_bargains(self) -> str:
        """
        Chạy công cụ scan.
        QUAN TRỌNG: Truyền 'self.memory' vào hàm scan của ScannerAgent.
        Mục đích: Để Scanner biết đường lọc bỏ những deal cũ.
        """
        self.log("Autonomous Planning agent is calling scanner")
        # Truyền bộ nhớ vào đây để Scanner lọc trùng lặp
        results = self.scanner.scan(memory=self.memory) 
        return results.model_dump_json() if results else "No deals found"

    # --- VÒNG LẶP CHÍNH (THE CORE LOOP) ---
    def plan(self, memory: List[str] = []) -> Optional[Opportunity]:
        """
        Chạy toàn bộ quy trình.
        :param memory: Danh sách các URL đã được xử lý trong quá khứ (Long-term memory).
        """
        self.log("Autonomous Planning Agent is kicking off a run")
        
        # 1. Nạp bộ nhớ từ bên ngoài (ví dụ từ Database hoặc Session state)
        self.memory = memory 
        self.opportunity = None
        
        # Reset lại lịch sử hội thoại cho phiên làm việc mới
        messages = self.messages[:] 
        
        done = False
        # 2. Vòng lặp "While not done" -> Đặc trưng của Agent
        while not done:
            # Gửi tin nhắn + Tools cho LLM
            response = self.openai.chat.completions.create(
                model=self.MODEL, messages=messages, tools=self.get_tools()
            )
            
            # 3. Kiểm tra xem LLM có muốn dùng Tool không?
            if response.choices[0].finish_reason == "tool_calls":
                message = response.choices[0].message
                
                # Thực thi Tool (Scan, Estimate, hoặc Notify)
                results = self.handle_tool_call(message)
                
                # Cập nhật lịch sử hội thoại để LLM biết kết quả của Tool
                messages.append(message)
                messages.extend(results)
            else:
                # Nếu LLM bảo xong rồi (không gọi tool nữa) -> Kết thúc vòng lặp
                done = True
        
        reply = response.choices[0].message.content
        self.log(f"Autonomous Planning Agent completed with: {reply}")
        
        # Trả về cơ hội (deal hời) tìm được để bên ngoài có thể lưu lại hoặc hiển thị UI
        return self.opportunity
Giải thích Logic quan trọng:
1.	memory: List[str]: Đây là cơ chế trạng thái (State). Trong thực tế, danh sách này sẽ được lưu trong cơ sở dữ liệu (như SQLite, Redis). Mỗi khi Agent chạy xong, chúng ta lưu lại các URL đã xử lý. Lần chạy sau, ta load lại danh sách này và đưa vào hàm plan.
2.	self.scanner.scan(memory=self.memory): Đây là sự phối hợp giữa "Sếp" (Planner) và "Nhân viên" (Scanner). Sếp đưa cho nhân viên danh sách đen (blacklist/memory) và bảo: "Đừng mang về cho tôi những cái này nữa".

import json
import logging
from agents.planning_agent import PlanningAgent # Import "Bộ não" chúng ta đã xây

class DealAgentFramework:
    MEMORY_FILENAME = "memory.json" # File lưu trữ dài hạn

    def __init__(self):
        self.memory = self.read_memory() # Khởi động là nạp ngay ký ức cũ
        self.planner = None 

    def read_memory(self):
        """Đọc danh sách các deal đã xử lý từ file JSON"""
        try:
            with open(self.MEMORY_FILENAME, "r") as file:
                return json.load(file)
        except FileNotFoundError:
            return []

    def write_memory(self):
        """Lưu ký ức xuống ổ cứng"""
        with open(self.MEMORY_FILENAME, "w") as file:
            json.dump(self.memory, file, indent=2)

    def run(self):
        """
        Hàm chính để chạy Agent.
        Được gọi bởi Gradio mỗi khi Timer kích hoạt.
        """
        self.init_agents_as_needed() # Chỉ khởi tạo Agent khi cần (Lazy loading)
        logging.info("Kicking off Planning Agent")
        
        # Gọi Planning Agent và truyền vào bộ nhớ hiện tại
        result = self.planner.plan(memory=self.memory)
        
        # Nếu tìm thấy cơ hội (deal hời)
        if result:
            self.memory.append(result) # Thêm vào bộ nhớ RAM
            self.write_memory() # Ghi xuống ổ cứng ngay lập tức
        return self.memory

o	Gradio là tiêu chuẩn vàng hiện nay để demo các mô hình AI vì nó hỗ trợ Python native, không cần biết HTML/CSS/JS.
o	Mở rộng: Bạn có thể host ứng dụng này lên Hugging Face Spaces hoàn toàn miễn phí để chia sẻ với bạn bè.
•	Log Streaming:
o	Kỹ thuật QueueHandler được sử dụng trong bài là một pattern rất hay để đưa log từ Backend (Python) lên Frontend (Web) trong thời gian thực. Nó giúp người dùng biết hệ thống không bị "treo" mà đang suy nghĩ.
Tổng kết Day 5: Bạn đã hoàn thành việc xây dựng "lớp vỏ" cuối cùng. Bây giờ, hệ thống của bạn là một ứng dụng trọn vẹn: Có não (Planner), có tay chân (Tools), có trí nhớ (Memory JSON) và có khuôn mặt (Gradio UI).
