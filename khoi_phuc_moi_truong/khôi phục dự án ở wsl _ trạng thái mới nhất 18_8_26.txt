# HANDOFF — RESTORE PROJECTS TỪ WINDOWS RECOVERY VÀO WSL2 UBUNTU

## 1. Mục đích của handoff này

Đây là handoff tiếp nối trực tiếp từ hai handoff trước:

1. recovery dữ liệu từ `ext4.vhdx` của WSL cũ trên SSD Netac bị lỗi;
2. trạng thái máy mới sau khi:

   * thay SSD;
   * reset/reinstall Windows;
   * cài lại WSL2 Ubuntu 24.04;
   * chuyển Ubuntu sang SSD D:;
   * cài Docker Desktop;
   * chuyển Docker storage sang D:.

Handoff này cập nhật thêm toàn bộ công việc trong session hiện tại:

* bắt đầu restore các project Linux cũ từ ZIP recovery trên Windows vào filesystem ext4 của WSL mới;
* đã restore hoàn chỉnh project đầu tiên:
  `AiAgent_t7_2026_wsl`;
* đã kiểm tra `.git`;
* đã cài Git;
* đã đăng nhập GitHub bằng GitHub CLI;
* đã xác nhận repository local kết nối đúng repository GitHub;
* đã cấu hình Git identity;
* đã xóa staging của project sau khi restore thành công.

**Quan trọng: mới chỉ hoàn thành restore dữ liệu cho `AiAgent_t7_2026_wsl`.**

Các project ZIP khác vẫn chưa restore.

Ngoài ra:

* chưa cài Python development stack cho Ubuntu mới;
* chưa cài `uv`;
* chưa dựng lại Python virtual environments;
* chưa cài Node/NVM cho project;
* chưa restore toàn bộ AI/dev configuration;
* chưa restore SSH;
* chưa chạy project;
* chưa kiểm tra runtime project;
* chưa chạy test/application của `AiAgent_t7_2026_wsl`.

Session tiếp theo phải tiếp tục từ trạng thái này, không bắt đầu lại từ đầu.

# 9. Nguyên tắc restore project đã thống nhất

Không giải nén ZIP bằng Windows Explorer rồi copy thư mục đã giải nén sang WSL.

Quy trình chuẩn đã quyết định là:

```text
Windows ZIP trên /mnt/d
        ↓
verify SHA256
        ↓
unzip -t kiểm tra CRC/archive
        ↓
unzip trực tiếp bằng Linux vào staging trên ext4
        ↓
kiểm tra cấu trúc
        ↓
rsync -a từ staging ext4 → destination ext4
        ↓
verify project / .git / permissions
        ↓
chỉ sau khi verify mới xóa staging
```

Lý do:

* tránh vấn đề metadata Linux khi giải nén bằng Windows;
* tránh permission/symlink/executable bit bất thường;
* tránh copy trực tiếp workload Linux từ DrvFS;
* kiểm tra được archive có thêm một tầng directory hay không;
* tránh tạo sai đường dẫn kiểu:

```text
/home/minhhieu/project/project/
```

```bash
SRC="/mnt/d/MinhHieuWSL/WSL_Recovery_2026/AiProduction_t6_2026_wsl.zip"
```

### B. Verify SHA256 từ manifest

Ví dụ:

```bash
grep -i 'AiProduction_t6_2026_wsl.zip' \
  /mnt/d/MinhHieuWSL/WSL_Recovery_2026/projects-zip.sha256
```

Sau đó:

```bash
sha256sum "$SRC"
```

Hai hash phải khớp.

### C. Test archive

```bash
unzip -t "$SRC" | tail -n 20
```

Yêu cầu:

```text
No errors detected in compressed data
```

### D. Xem root structure

```bash
zipinfo -1 "$SRC" | head -n 50
```

Không giả định trước archive có một tầng hay nhiều tầng directory.

### E. Tạo staging riêng

Ví dụ:

```bash
mkdir -p /home/minhhieu/.restore-staging/AiProduction_t6_2026_wsl
```

### F. Unzip trong WSL ext4

```bash
unzip "$SRC" \
  -d /home/minhhieu/.restore-staging/AiProduction_t6_2026_wsl
```

Không dùng:

```bash
sudo unzip
```

```bash
du -sh ...
ls -la ...
find ... -maxdepth ...
find ... -name .git
```
